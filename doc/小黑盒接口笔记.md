# 小黑盒接口笔记（只读已验证部分）

> 状态：2026-10-21 实测。小黑盒**没有公开稳定的自动化 API**，以下全部来自第三方公开实现
> （[better-XiaoHeiHe](https://github.com/k1m0206/better-XiaoHeiHe)、
> [xiaoheihe-cli](https://github.com/AaronZ345/xiaoheihe-cli)、
> [astrbot_plugin_xiaoheihe_adapter](https://github.com/674537331/astrbot_plugin_xiaoheihe_adapter)）
> 与本人登录态下的真实请求。字段随时可能变，改之前先看这里、再改 `lib/xhh/`。

## 鉴权

- Cookie：`user_pkey` + `user_heybox_id`（网页登录态，导入到 `data/xhh-auth.json`）
- 每个请求都要 `hkey` / `_time` / `nonce` 签名（算法见 `lib/xhh/sign.js`）
- 认证请求额外带 `heybox_id=<uid>` 参数
- 401 / 403 → 登录失效；`status: "failed"` → 普通失败

## 已实测通过的只读接口

| 用途 | 路径 | 关键参数 | 返回要点 |
|---|---|---|---|
| 账号检查 | `GET /bbs/app/api/user/permission` | `heybox_id` | 成功时返回**权限字段字典**（17 个），没有 `status: ok` |
| 关键词搜索 | `GET /bbs/app/api/general/search/v1` | `q`、`search_type=link`、`offset`、`limit` | `result.items[]` |
| 推荐流 | `GET /bbs/app/feeds` | `pull=0`、`offset=0` | `result.links[]` |
| 帖子/楼层 | `GET /bbs/app/link/tree` | `link_id` | `result.link` / `result.comments` / `total_page` / `has_more_floors` |
| 通知（@/回复） | `GET /bbs/app/user/message` | `message_type=16/17`、`offset`、`limit`、`no_more=false` | `result.messages[]` |
| 我的近期评论 | `GET /bbs/app/comment/user` | `offset`、`limit` | 用于写操作后核对（防重复） |

**搜索参数注意**：`search_type` 只能是 `link`（帖子）或 `user`（用户）。传 `post`、`1` 都返回 0 条——不是没结果，是参数错了。

## @ 通知（message_type=17）的真实结构

2026-10-21 实测，某人在帖子里 @ 她之后：

```json
{
  "message_id": "4436900197",
  "message_type": "17",
  "state": 0,                       // 0 = 未读
  "timestamp": 1792593238,
  "linkid": "194604019",            // 帖子 ID
  "link_title": "……",
  "link_tag": "27",                 // 分区
  "link_userid": "68208561",        // 楼主
  "userid_a": "92866156",           // 发评论的人
  "userid_b": "21987774",           // ★ 被 @ 的人（她）
  "comment_a_id": "980889540",      // 这条评论的 ID
  "root_comment_id": "980889540",   // 楼层根 ID（主评论时两者相同）
  "comment_a_is_cy": 0,
  "text": "@了我",                   // 纯文本正文
  "comment_a_text": "<a data-user-id=\"21987774\" href=\"https://api.xiaoheihe.cn/open_inapp/#heybox://…\" target=\"_blank\">@憨咸_悉</a>",
  "user_a": "{\"username\":\"dirrt\",\"userid\":\"92866156\",…}",   // JSON 字符串，要二次 parse
  "user_b": "{\"username\":\"憨咸_悉\",\"userid\":\"21987774\",…}"  // 同上
}
```

### 结论

1. **@ 关系可以直接判断**：`userid_b === 自己的 uid` 就是被 @ 了，不需要解析 HTML。
2. 想拿上下文：`linkid` → `/bbs/app/link/tree`，`comment_a_id` → 在楼层树里定位评论。
3. 想回复：`link_id = linkid`，`reply_id = comment_a_id`，`root_id = root_comment_id`（主评论两者相同）。
4. `message_type` 传 16 或 17 都能拿到这条；服务端返回的记录里自己标的是 `"17"`。
5. `user_a` / `user_b` 是**字符串**，直接当对象用会得到 `undefined`，必须 `JSON.parse`。

## 发评论（尚未启用，仅记录契约）

```
POST https://workshopapi.xiaoheihe.cn/bbs/app/comment/create
Content-Type: application/x-www-form-urlencoded

is_cy=0
link_id=<帖子 ID>
reply_id=<评论 ID | -1>      // 主评论 -1
root_id=<楼层根 ID | -1>
text=<正文>
```

URL 上除常规签名外还要 `_rnd=15:<签名>` 和 `web_version=3.0`。

### 幂等（按机主要求，实现写操作前必须做）

- 发送前先落库 `pending`，带上 `link_id + reply_id + text 指纹`；
- `pending` 未决时**禁止**再次 POST 同一条；
- 网络超时 / 5xx / 结构异常 → 记为 `send_unknown`，先用 `GET /bbs/app/comment/user` 核对是否已入库；
- 明确业务失败才算失败；`send_unknown` 绝不自动重发。

## 已知风险

- 接口非公开契约，hkey 算法和字段都可能变；
- Cookie 会过期（需要重新导入）；
- 自动化读写有封号风险，尤其新账号；
- 只读阶段也不宜高频：B 站搜索 3 秒间隔都会触发 -412，小黑盒只会更严。
