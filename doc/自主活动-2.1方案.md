# 自主活动 2.1 修改方案（2026-10-31 机主定稿）

> 来源：机主 2026-10-31 01:38 发来的完整规格。**这是设计稿，还没实现。**
> 当前实现在 `plugins/autonomous/`，差距见文末「现状 vs 目标」。

## 一、目标

在现有 `autonomous` 插件上增加：

1. 每次唤醒最多进行**两次不同类型的行动**。
2. 第二次行动根据第一次的**实际结果**重新决定。
3. 保留本轮发现、选择理由、实际结果和后续想法。
4. 下次唤醒时，可以延续之前感兴趣的内容，也可以改变方向。
5. 将值得保留的自主经历写入日记。
6. 将最近的相关经历适量注入 DSH 聊天上下文。

**暂不实现** `activityProfile`、长期偏好评分、兴趣权重、向量数据库、新的遗忘系统。

## 二、保留现有运行限制

| 项目 | 规则 |
|---|---|
| 唤醒间隔 | 每 3 小时检查一次 |
| 活动窗口 | 最长 30 分钟 |
| 模型调用 | 每轮最多 6 次 |
| 行动次数 | 目标 2 次，最多 2 次 |
| 行为要求 | 同一轮的两次行动类型不同 |
| 每轮分享 | 最多 2 次 |
| 每日评论 | 最多 3 条 |
| 每日发帖 | 最多 1 篇 |
| 安静时段 | 遵守现有不对外打扰规则 |
| dryRun | 只模拟与记录，不产生外部写入 |
| 无合适行为 | 允许提前结束 |

### 自由活动原则

**她可以连续两次选择不同的事情，但不要求两次都有成果。**

- 浏览了内容却没发现有趣的东西，是正常活动，不算失败。
- 尝试画画但没有灵感，可以停止，不必强行生成作品。
- 想分享却发现内容普通，可以选择不分享。
- 第二次行动可以只是探索新的话题，不必产生可展示的成果。
- 两次活动都没有成果，也可以正常结束，不需要补做任务。
- 不为了完成行动次数而强行评论、分享、聊天、写日记或制造结果。

**行动次数衡量的是她拥有多少次探索和选择的机会，而不是完成了多少任务。**

探索、查看内容和尝试创作可以记录为活动经历；实际执行成功与否应单独记录。
`finish` 不计入行动次数，但始终允许选择。30 分钟是时间上限，不代表必须持续调用模型。

## 三、活动流程

```
原：唤醒 → 抓内容 → 模型决策 → 执行一次 → 结束

新：唤醒 → 读取上轮进度 → 自由探索 → 第一次决策 → 执行或尝试 → 获取反馈
     → 更新候选 → 第二次决策 → 执行或尝试 → 整理经历 → 休息
```

**第一次行动**加载：当前可用能力与权限、当日额度和安静时段、上轮行为冷却、
上轮未完成的探索方向、已有内容和去重记录。
模型选行动并给出简短 `goal` / `why` / `next`。执行后程序保存**真实结果**
（包括"没发现值得分享的内容"）。

**第二次行动**必须在第一次结果返回后重新选择：

- 排除第一次已经用过的行为类型；
- 遵守本轮和跨轮冷却；
- 可以继续同一兴趣话题，但换行为方式；
- 第一次没成果就换别的活动；
- 没有合适选择就直接结束。

例：第一次在小黑盒浏览猫咪帖，没找到有趣内容 → 第二次想画猫但没灵感 → 结束。
**这仍是一轮正常的自主活动。**

## 四、活动反馈闭环

每次行动结束后统一产生结构化反馈：

```json
{
  "action": "draw",
  "goal": "画一只趴在窗台上的猫",
  "why": "刚才看到一张有趣的猫咪图片",
  "result": "no_output",
  "resultSummary": "尝试构思，但暂时没有合适的灵感",
  "reflection": "下次可以换个画风试试",
  "next": "有机会继续尝试猫咪插画",
  "nextStatus": "pending"
}
```

- `result`：程序确认的实际结果 —— `success` / `failed` / `skipped` / `no_output`
- `resultSummary`：实际发生了什么
- `reflection`：简短评价或新发现，可为空，由现有决策模型顺带生成（**不额外调模型**）
- `next` / `nextStatus`：想继续的方向与状态

**`no_output` ≠ `failed`。** 没有产出可能是主动不分享、没灵感、没发现值得留的，
不代表工具执行失败。**真实结果由程序确认，主观评价由模型表达，二者不能混淆。**

## 五、反馈如何影响下一次

暂不建长期偏好档案，只加轻量的近期兴趣与后续计划：

```json
{
  "pendingNextStep": {
    "topic": "猫咪插画",
    "intent": "尝试另一种画风",
    "sourceAction": "draw",
    "status": "pending"
  }
}
```

下一次唤醒：检查是否有未完成方向 → 判断现在是否仍有价值 → 有就继续、
没兴趣/过时/能力不可用就放弃 → 也可以完全选新话题。

**不因为记录了 `next` 就必须执行。** 完成后标 `completed`；明确放弃标 `abandoned`；
**不得把计划当作已完成的事实。** 每轮最多保留少量近期计划，避免积压。

## 六、行为冷却与活动差异

沿用 2.0 的冷却机制。行为用稳定的 `actionId` + `actionType`：

```
xhh_share   → share      bili_share  → share
xhh_comment → comment    draw        → draw
chat        → chat       diary       → diary
```

- 同轮默认不重复相同 `actionType`；
- 跨轮保留既定的平台与行为冷却；
- **冷却只用于避免机械重复，不能被解释为她不喜欢某类活动**；
- 未获权限、额度不足、冷却中的行为不进候选列表；
- 主动尝试但没产出可以计入行动次数；**工具失败、未实际尝试的选择，不得伪装为有效行动**；
- `finish` 永远可选，不参与冷却。

## 七、存储分工

| 位置 | 存什么 |
|---|---|
| `data/autonomous.json` | 运行状态、最近的行动与结果、冷却信息、`pendingNextStep`、短期摘要 |
| `data/autonomous-log.md` | 完整过程：时间/来源/行动类型、goal/why/next、真实结果（含无成果）、分享来源、失败原因 —— 排查与回顾的事实依据 |
| 日记 | **仅值得保留的经历**：发现特别感兴趣的内容、完成一张画、形成新想法、探索引出新问题、与之前交流产生联系。普通浏览/失败重试/无意义重复不写。遵守原有等级与去重规则 |
| proactiveNote | 最近 2 轮、24 小时内的相关经历，简短事实摘要，不注入完整日志 |

**不把普通活动写入 `learned.json`。**

proactiveNote 里要明确区分：实际看过什么、实际做过什么、为什么感兴趣、
哪些想法尚未执行。**已由 hotNote 补入的主动消息，不重复提供原文。**

建议提示词：

> 以下是你近期的自主经历，仅用于理解和接续当前对话。不必主动汇报活动过程，
> 也不必刻意提起；话题相关时自然使用即可。

**不得把这些记录当成新的强制待办。**

## 八、避免汇报腔

自主经历是内部上下文，不是发给老大的工作报告。不要为了证明自己有在活动而反复汇报
行程、成果或待办。但老大主动询问、或相关发现确实值得分享时，可以自然交流。

继续沿用 `ai-tone-check` 的 H 族监控，结合真实上下文判断是否出现不自然的状态播报。

## 九、实现要求

- 复用已有决策和执行模块，**不新增独立调度器**；
- 不增加模型调用预算；
- 不重新实现已有的 QQ / B站 / 小黑盒 / 绘画工具；
- 活动完成后用现有结构化结果整理反馈；
- 状态写入**幂等**，避免失败重试造成重复日记或重复计数；
- 模型调用耗尽时保存已有进度并安全结束；
- 工具失败不得伪装成成功；
- 第二次行动不得绕过每日额度和权限；
- 不以产出数量衡量完成质量；
- 保持原有日志、密钥保护与回归测试。

发帖、评论、回复等公开操作继续遵守当前权限与审核配置，**不因第二次行动默认扩大写入权限**。

## 十、验收标准

1. 每轮最多两个行动，且类型不同。
2. 第二次行动确实依据第一次结果重新选择。
3. 没有合适行动时可以提前结束。
4. 两次行动均无成果时仍可正常结束，不触发补做。
5. `no_output` 与 `failed` 能正确区分。
6. 冷却和每日额度正常工作。
7. 活动结果能正确保存到日志。
8. 有意义的活动可以进入日记，且不会重复写入。
9. 下一次活动可以延续上轮计划，也可以主动放弃。
10. QQ 聊天能按需利用最近自主经历，不出现明显汇报腔。
11. 未完成计划不会被描述为已完成。
12. 不增加额外模型调用，不破坏原有自动活动功能。

## 十一、实施顺序

1. 改状态机：支持两次不同类型行动及无成果正常结束。
2. 每次行动加统一反馈结果，区分成功 / 失败 / 无成果。
3. 接 `pendingNextStep`，跨轮兴趣延续。
4. 接日记与 proactiveNote。
5. 跑原有回归 + 新增测试，观察真实表现。

暂不开发 `activityProfile`，也不把自主活动迁移到 DSH。

> **最终原则：她的空闲时间是用来探索、尝试和自由选择的，不是用来完成产出指标的。**

## 现状 vs 目标（2026-10-31 核对代码）

| 项 | 现状 | 2.1 要求 |
|---|---|---|
| 每轮行动数 | **1 次**（`runSession` 一次决策一次执行） | 最多 2 次，类型不同 |
| 第二次决策 | 无 | 依据第一次真实结果重新选 |
| 结果字段 | 只有 `stopReason` / `error` / 各动作的 `mode` | 加 `result` / `resultSummary` / `reflection` / `nextStatus` |
| `no_output` vs `failed` | 没有区分（`finish` 直接不记） | 必须区分 |
| 冷却 | 只有去重（`isSeen`）和每日额度 | 加 `actionId` / `actionType` 冷却 |
| `pendingNextStep` | 是**字符串**（`st.pendingNextStep = decision.next`） | 改成对象（topic/intent/sourceAction/status） |
| 日记 | 已有 `activityMemory` + 去重（10-31 加） | 保留，按"值得保留"筛选 |
| proactiveNote | 已有 `buildAutonomousNote`（24h/2 轮/hotNote 去重） | 保留 |
| H 族监控 | 已有（10-31 加） | 保留 |

实施时优先改 `runSession` 的结构：把"一次决策 + 执行"抽成可调用两遍的单元，
两遍之间用第一遍的真实结果更新候选，再判断要不要第二遍。
