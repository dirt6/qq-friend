# 小鲸鱼的日常 · 生活观察面板 v1.0（2026-10-31 机主定稿）

> **这是设计稿，还没实现。**
> **硬约束：原有功能一律不动、不减、不降权。** 新页面只加不改，管理能力全部保留。
> 本方案包含并扩展了 `doc/自主活动-面板可视化方案.md`（原待办 1.6），以本文为准。
> 活动详情要展示的 `result` / `reflection` / `next` **依赖 `doc/自主活动-2.1方案.md`** 先落地。

## 一、目标

把现有 8899 管理面板升级为「生活观察 + 原有管理功能」的本地网页。

1. 直观看到小鲸鱼最近的自主活动；
2. 浏览她的画作、日记和活动反馈；
3. 了解她为什么选某件事、做完后的想法；
4. 界面温暖自然，像她自己的生活空间；
5. **保留原有经验管理、画廊、状态管理等全部功能**；
6. **不改变自主活动、模型调用、记忆和聊天逻辑**。

本次**不做**：网页聊天、长期偏好系统、机器人后端重写。

## 二、技术方案

### 2.1 原生网页，零依赖

HTML + CSS + 原生 JS + 现有 Node 服务。**不引 React/Vue/构建工具/新的前端服务。**

### 2.2 前端文件独立

```text
QQ-agent/
├── scripts/web-panel-server.mjs      # 只负责：HTTP、静态文件、数据接口、原有管理接口
├── web-panel/
│   ├── index.html
│   ├── style.css
│   ├── app.js
│   └── modules/{home,activities,gallery,diary}.js
└── data/{autonomous.json, autonomous-log.md, drawings/, ...}
```

可按实际目录微调，**不强行迁移已有功能模块**。前端不直接访问磁盘文件。

### 2.3 分阶段拆分 PAGE

把 `PAGE` 模板里的 HTML/CSS/JS 分别抽成独立文件。拆分时：

- **不改现有 API 路径与响应结构**；
- **不改已有面板功能和权限**；
- 不改机器人运行逻辑；
- 不把服务器私有数据嵌进页面；
- 前端代码不再嵌在 JS 模板字符串里。

**先确认拆分前后功能等价，再加新页面。**

## 三、页面结构

### 3.1 首页「小鲸鱼的日常」

生活记录布局，不是管理后台仪表盘。

**今日概览**：最近一次醒来的时间、今天活动了几轮、画了几张、最近写的日记、
当前是否正在自主活动。**状态以真实日志为准，不能靠时间推断。**

**最近的生活片段**（按时间）：看过哪些帖子、画过哪些画、主动分享过什么、
有没有发现有趣的东西、有没有留下后续想法。简短摘要，点击看详情。

**今天的画作**：真实作品缩略图 + 创作评价。

**日记摘录**：最近一篇的简短摘录 + 完整入口。

**没有记录时显示自然的空状态，不编造活动内容。**

### 3.2 自主活动页

时间线 + 活动卡片：时间、平台与行为类型、浏览对象或作品名、`why`、`goal`、
`result`、`reflection`、`next`。

要能区分：**已完成 / 探索后无成果 / 主动放弃 / 工具失败 / 跳过**。
`no_output` 不等于失败。

支持按日期 / 平台 / 类别筛选。可查看原始链接，但**不在页面上执行评论或发布**。

### 3.3 画廊

复用现有 `index.json` 和图片存储：缩略图、点击放大、时间、画风、创作原因、
画完后的评价、相关活动记录。

**没有关联反馈就正常显示作品，不补造评价。** 不重复开发绘画生成与发布。

### 3.4 日记

复用现有目录和分级：日期、标题、内容、重要程度、来源于自主活动的记录（如能可靠识别）。
支持按日期和关键词查找。**只做阅读界面**，原有写入与等级调整能力不变。

### 3.5 原有管理功能

**必须保留**：经验管理、状态与运行信息、现有画作管理、已实现的设置与操作。

通过「管理」入口进原页面区域，**不要求一次性重新设计所有管理界面**。
原有写入功能**不因新增观察页面而扩大权限**。

## 四、视觉风格

温暖、清爽、有生活感的日漫系个人空间，但**不过度动画、不复杂背景**。

浅米白背景，淡蓝/浅绿辅助；柔和卡片、适度圆角；画作作为主要视觉元素；
日记保持文字阅读体验；活动时间线清楚但**不呈现为任务完成清单**；
图标 + 文字结合，不靠颜色区分状态；桌面优先、兼容手机。

深色模式后续再说，不是第一阶段必做。**不用虚构的活动、作品或情绪装饰页面。**

## 五、数据设计

### 5.1 事实来源

| 数据 | 来源 |
|---|---|
| 自主活动 | `autonomous-log.md`、`autonomous.json` |
| 画作 | 画廊 `index.json` |
| 日记 | 日记文件 |
| 经验 | `learned.json` |
| 运行状态 | 现有状态/日志接口 |

面板是独立进程，**只能读已持久化的数据**，读不到主进程内存。

### 5.2 历史优先用日志

如果 `autonomous.json` 只保近期状态，就不能依赖它给完整历史。
**先检查 `autonomous-log.md` 的真实结构**；缺结构化字段可在记录流程里补，
**但不得另建一套与原始记录矛盾的事实系统**。**不猜测日志内容生成 `reflection`。**

### 5.3 反馈展示规则

`goal` 原本想做什么／`why` 为什么选／`result` 程序确认的真实结果／
`reflection` 模型留下的评价／`next` 尚未完成的想法。

**没有 `reflection` 就显示「未留下评价」，不调模型补写。**
**没实际看过作品就不能展示虚构的具体画面评价。计划与完成状态必须区分。**

## 六、接口与安全

优先复用现有接口。确需新增只读接口时，建议（实施前先查现有路由，避免重复）：

```
GET /api/life/summary
GET /api/life/activities
GET /api/life/gallery
GET /api/life/diary
```

要求：

1. 观察页面**不调模型**；
2. 观察页面**不执行发帖、评论、私聊、绘画**；
3. 不直接暴露任意本地文件路径；
4. 图片访问**限定在已有授权目录**；
5. 外部内容与模型生成文字**安全转义**；
6. 保留现有访问控制，**默认仅本机**，不开公网；
7. 页面/接口不暴露 API Key、Cookie；
8. 日志缺失、损坏、旧字段不存在时**安全降级**；
9. 历史记录**按需加载**，避免一次读过大文件；
10. 页面只读 ≠ 服务器所有接口只读，**原有管理接口继续校验权限**。

## 七、开发顺序

### 第一阶段：拆分原有面板（不加新功能）

检查现有 PAGE、接口、事件绑定和测试 → 拆成独立 HTML/CSS/JS → 保留现有功能/URL/接口 →
跑面板测试 → 重启面板浏览器验收。

### 第二阶段：生活首页

首页布局、最近活动摘要、最近画作、日记摘录、无数据状态。

### 第三阶段：活动详情

时间线与筛选、`goal/why/result/reflection/next`、关联帖子与画作、详细记录。

### 第四阶段：视觉

样式排版、屏幕适配、统一原有页面基础样式、修显示问题。

**不在同一次提交里同时做前端拆分、自主活动逻辑重构、视觉全面改版。**

## 八、工程注意事项

### PAGE 模板问题

原页面用嵌套模板字符串，曾出现 `\n` 被外层提前解析导致前端脚本损坏。
拆分时不能把这个坑带进新结构。

**只要改了 PAGE 或页面生成逻辑，就必须跑 `web-panel-page-test`。**
拆分后还要**验证浏览器实际加载的脚本内容**，不能只看 HTTP 200。

### 进程重启

改 `scripts/web-panel-server.mjs` → **必须重启面板进程**。
独立静态文件能否刷新生效取决于实际静态服务与缓存设置，**不得未经验证就宣称热更新可用**。
改自主活动持久化源码 → **重启 QQ-agent 主进程**。

### 原有数据保护

**不迁移、不清空、不覆盖**历史画廊、日记、经验和自主活动记录。
数据格式变化时保留向后兼容与必要备份。

## 九、验收标准

1. 原有面板功能完整保留。
2. HTML/CSS/JS 已独立拆分。
3. `web-panel-page-test` 和现有回归测试通过。
4. 新首页能展示真实自主活动摘要。
5. 画廊能预览真实作品。
6. 日记能正常阅读。
7. 活动详情能区分真实结果和模型评价。
8. 无成果活动正常展示，不显示为失败。
9. 空评价不自动补写。
10. 旧数据、缺失字段、损坏记录不会导致整页崩溃。
11. 浏览器控制台无阻断性错误。
12. 新增观察页面不触发模型调用或外部写入。
13. 桌面端和手机端布局正常。
14. 重启面板后所有功能真实可用。
15. 现有自主活动调用预算、权限和频率保持不变。

## 十、明确不做

网页聊天、活动实时操控、自主活动重新调度、`activityProfile`、长期情绪系统、
新的模型调用、新的记忆数据库、重写 QQ-agent/DSH 通信、面板开放到公网。

> **最终目标：让老大能自然地看看小鲸鱼的日常，而不是每天审查一份任务执行报告。**

| 项 | 现状 | 目标 |
|---|---|---|
| 前端形态 | `PAGE` 模板内嵌，572 行（占文件 36%） | 拆成 `web-panel/` 下的独立文件 |
| 面板板块 | ①状态 ②人设 ③NapCat ④机器人 ⑤画 ⑥经验 ⑦表情，全部内嵌 | 保留全部 + 加生活首页/活动页/日记页 |

| 打包 | `files: ["**/*", "!data/**", …]` | 新增 `web-panel/` 会被包含，无需改 |

### 实施建议

1. **第一阶段先只做拆分**，跑通测试、浏览器验收，**不碰任何业务逻辑**；
2. 拆分完成后，改 CSS 是否免重启要先实测（服务端每次 `readFileSync` 才行，不能缓存）；
3. 生活首页的数据接口**尽量复用**现有 `/api/drawings`、`/api/logs`，新增的 `/api/life/*` 只读；
4. 活动页要等 2.1 的 `result/reflection` 落地，否则只能显示旧字段（`stopReason` 一类）；
5. 原有管理区**原样保留**，先搬到独立文件，不重排、不改交互。
