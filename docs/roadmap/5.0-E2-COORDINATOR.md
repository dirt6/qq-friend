# 5.0-E2：统一执行协调器验收报告

> 实现：`src/autonomous/coordinator.js`
> 专项：11/11；临时 execution store + Fake executor
> 结论：**E2 PASS（隔离）**

## 一、职责

- 串联 A1/A2/A3/A4/B/C/D；
- 只调用当前需要的模块：无 activityState 不选活动，无 sharingInput 不判分享，无 memoryInput 不治理；
- selectedActivity **不是授权**；`share_now` 不发送；D 不写领域；B 只提供上下文；
- 执行必须同时具备：receipt + 匹配 planHash + 未过期 authorization + 注入 execute + 未暂停。

## 二、状态流

`decision_recorded → authorization_pending → authorized → started → succeeded/failed/unknown`

- 无授权：停在 decision_recorded；
- 授权不匹配/过期：不执行；
- `conversation_continue` 不作为自主执行；
- executor 超时 → unknown，不自动 succeeded/failed；
- executor 抛错 → failed，不自动重试；
- 同一 receipt 已终态/started/unknown → 重复 run 不执行；
- pause → 不开始执行。

## 三、边界

- execute 是注入函数，不接受任意 shell/路径参数；
- 不提供发送函数；C 仅返回决策；
- D 只返回 routedTo，协调器不调用领域写；
- execution store 文件由调用方显式提供，无默认生产路径。

## 四、测试

11/11：无授权、plan 篡改、过期、有效授权成功、重复 run、pause、timeout→unknown、share 不发送、memory 只路由、conversation 不执行、临时目录。

## 五、遗留

1. authorization token 无签名，依赖调用方/文件权限；
2. executor 白名单/参数校验由上层注入实现；
3. 未接生产 autonomous/QQ/模型；
4. unknown 人工对账流程待 E4。
