# 5.0 今晚统一部署清单

> 结论：**E6 代码已就绪，但生产启用条件未齐**。Runtime 已实例化、G2/G3 默认 disabled、G3 过 Coordinator、SendQueue 已注入；生产尚未配置独立 control token/HMAC keys/单目标，且未获重启授权。
> 本清单只作为下一次窗口步骤，不在本任务执行。

## 一、目标

- 窗口 HEAD：部署时 `git rev-parse HEAD`（当前 E6 提交）；
- 生产现状：旧入口运行，G1 paused；token/ACL 正常；autonomous/silence disabled；
- 目标默认：G1 paused；G2/G3 disabled；自动调度 disabled；旧 autonomous 禁止绕过。

## 二、重启前必须补齐（阻断）

1. 配置独立 `data/5.0-runtime/control-token`（不得复用 G1 token）；
2. 配置 `data/5.0-runtime/auth-keys.json`（G2/G3 HMAC 密钥，ACL 保护）；
3. 配置 `runtime.g3Target`（唯一 QQ 私聊目标，空则 G3 不可运行）；
4. 确认 E6 启动测试：G1 paused、G2/G3 disabled、0 模型/发送、token 分离；
5. 备份 config/ACL/10 类 hash；准备回滚。

未完成上述项前，不重启。

## 三、窗口步骤（补齐后）

1. 记录 HEAD、工作区、未跟踪文件；
2. 备份 config/ACL/10 类 hash；
3. 确认 G1 token/ACL；确认 `data/5.0-runtime/token` 与 G1 token 分离；
4. 托盘退出或 PID 精确停止旧 Electron；NapCat 不动；
5. 启动新 HEAD；
6. 验证：
   - G1 paused；
   - G2/G3 disabled；
   - run 返回 DISABLED；
   - 无模型/工具/写入/发送；
   - 10 类 hash SAME；
7. 保持 paused/disabled；不执行 G2/G3 生产动作。

## 四、G2 单条授权步骤（以后）

1. 单独生成 G2 action authorization（HMAC，绑定 receipt/planHash/learned/内容）；
2. 启用 G2（仅 learned）；
3. 单条 run；
4. 验证 learned 写入、Memory Hub 读取、幂等；
5. 立即 pause/disable；
6. 用户纠正后验证旧推断不覆盖。

## 五、G3 单目标授权步骤（以后）

1. 单独生成 G3 action authorization（HMAC，scope=send，绑定 target/text）；
2. 启用 G3（仅一个 QQ 私聊目标）；
3. 先 dry-run；
4. 单次真实发送；
5. 验证 receipt、journal、去重、unknown 不重发；
6. 立即 pause/disable。

## 六、回滚

- 代码回滚到窗口前 commit；
- config/ACL 恢复备份；
- 不 reset/删业务数据；
- 若 G2/G3 已产生写入：按 receipt/幂等键对账，不盲删；
- 若 G3 unknown：不重发，查询 OneBot/QQ 记录后人工对账。

## 七、失败触发

- G1 非 paused；
- G2/G3 意外 enabled；
- 启动即模型/工具/发送；
- 10 类 hash 非预期；
- token 串用；
- 任一 pause 无效。
