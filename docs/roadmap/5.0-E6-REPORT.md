## 二、职责分离

### 运行状态：`data/5.0-runtime/state.json`

只存：

- `paused`
- `g2` / `g3` 开关
- 预算计数 `budget.day/actions/sends`
- `lastRecovery`
- 损坏标记 `degraded`

规则：

- 启动**强制 paused**；
- 启动**强制 G2/G3 disabled**（fail-closed；不恢复上次 enabled）；
- flags 只能在启动后由独立控制 token 重新显式打开；
- state 损坏 → `degraded=true`，paused，拒绝 run；
- 预算按日重置并持久化；动作在尝试前计数，崩溃不会少算。

### 权限凭证：独立文件

- `data/5.0-runtime/control-token`：控制 API，`x-5.0-token`，与 G1 token 分离；
- `data/5.0-runtime/auth-keys.json`：G2/G3 HMAC 密钥，不进入 state；
- 缺失/损坏 → 控制 401 或 action authorization 失败，fail-closed。

### G3 intent：`data/5.0-runtime/g3-send-journal.json`

- 发送前写 `sending`；
- 崩溃后恢复：`sending → unknown`；
- 后续同 fingerprint 返回 UNKNOWN，**不自动重发**。

## 三、恢复规则

- 启动：Runtime 强制 paused；
- `execution-store` 中 `started` → UNKNOWN；
- G3 `sending` → UNKNOWN；
- unknown 不自动重放；
- 预算/pause 从 state 恢复；G2/G3 flags 启动强制 false（fail-closed）；
- state 损坏 fail-closed。

## 四、G2/G3 接入

- G2：`learned-adapter` → `memoryWriter` → Coordinator；
- G3：`qq-adapter` → `sendShare` → 真实 `SendQueue`；
- Runtime 是唯一生产入口；G1 仍独立只读、paused；
- G3 必须同时持有：
  - Coordinator 级 action 授权（绑定 receipt/planHash/activity/params）；
  - `qq.send` 级 HMAC（绑定 target/text/scope=send/nonce）；
  - 固定 `runtime.g3Target`，请求不能替换。

## 四·一、只读空闲路径（新增）

- `src/autonomous/readonly-adapter.js`：B站公开榜单只读，过滤不安全内容；失败返回错误，不抛；
- 小黑盒匿名接口不可用，不伪造登录态，不实现；
- `readonly` 是独立开关，默认 false；必须经 Coordinator 显式 run；
- 无记忆写入、无发送、无模型调用；仅外部 GET；
- 不自动调度，只提供手动运行路径。
