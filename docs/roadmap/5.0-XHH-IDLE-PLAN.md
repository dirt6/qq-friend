## 二、评论为什么走浏览器

小黑盒评论 API 会返回：

```text
评论功能暂不可用
```

原因是评论接口还需要浏览器会话 token（`x_xhh_tokenid`），扫码登录只给 pkey。  
所以不走 API 写评论，改走有头 Edge：

```text
scripts/xhh-browser-comment.mjs --link-id <id> --text "..."
```

默认行为：

- 启动有头 Edge；
- 打开帖子；
- 填入评论；
- 截图；
- **不点发送**；
- 留窗口给你检查。

只有显式：

```text
--send
```

才点发送。  
**必须用备用号，不用主号。**

已验证：填入成功、发送按钮可见、没有发送。

## 五·一、自动回复可行性（2026-11-05 实测）

只读探测：`node scripts/xhh-token-probe.mjs [--link-id <id>] [--headful]`
单次评论实测：`node scripts/xhh-comment-once.mjs --link-id <数字id> --text "..." --confirm`
（只输出键名/布尔，不打印任何凭据值。）

### 实测结果

| 步骤 | 结果 |
|---|---|
| 持久化 Edge profile | `data/xhh-edge-profile` 存在 |
| 浏览器会话 token | **`x_xhh_tokenid` 能从帖子页 cookie 拿到**（只在内存用，不落盘） |
| 无头 Edge | 可启动、可打开帖子页 |
| 只读登录接口 | `/bbs/app/user/message` 在 pkey-only 与 +token 两种情况下都 `ok` |
| API 评论（hex 分享码） | `failed`：`请求参数 "link_id" 格式错误`（API 要数字 id） |
| API 评论（数字 id + token） | `failed`：**`评论功能暂不可用`** |
| 浏览器有头通道 `--send` | **成功**，评论已出现在帖子下 |
| 结果核对（只读） | 帖子数据里能读到该评论；截图 `data/xhh-comment-sent.png` |

### 结论

1. **API 评论不可行**：带浏览器 token + 正确数字 `link_id` 仍被服务端拒绝（“评论功能暂不可用”），
   这不是缺 token 的问题，不要再重复尝试；
2. hex 分享码要先解析成数字 `link_id`（`/bbs/app/link/tree` 返回的 `link.linkid`），
   否则 API 会报 `link_id 格式错误`；
3. **自动回复只能走浏览器有头通道**：`scripts/xhh-browser-comment.mjs --send`
   （默认只填不发；发送是一次性外部动作，失败不重发）；
4. 无头模式下评论区不渲染，自动回复必须用有头 Edge；生产上若要接，需要“填 → 截图 → 确认 → 发送”的流程，
   不默认全自动。
