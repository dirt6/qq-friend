## 二、输入契约

```js
{
  now?: number|string,
  closure: A2Output,                    // 必填；缺失 → wait
  purpose: A1Output | Candidate[],      // 可为空
  state: {
    goals?: [], pending?: [], recentRounds?: [], recentActions?: [], topics?: [],
    budget?: { remainingCost?, remainingTokens?, remainingActions?, maxRisk? }
  },
  budget?: {...}, limits?: {
    maxRisk?: 'low'|'medium'|'high',
    minConfidence?: number,
    cooldownMs?: number,
    allowedActivities?: string[]
  }

```

非法顶层/字段类型 → `INVALID_INPUT`；坏候选跳过；输入不修改。

## 三、输出契约

```js
{
  ok: true,
  decision: 'selected'|'wait'|'no_action',
  selectedActivity: {
    type, title, priority, risk, budgetEstimate, candidateId,
    sourceGoalIds, sourcePendingIds, needsConfirmation
  } | null,
  sourcePurposeIds, sourceGoalIds, sourcePendingIds,
  reason,
  rejectedAlternatives: [{candidateId,type,title,reason}],
  risk: 'low'|'medium'|'high'|'none',
  budgetEstimate: {cost,tokens,actions},
  needsConfirmation: false,
  uncertainties: [{code,detail}],
  diagnostics
}
```

**selectedActivity 不是执行授权**；执行层必须再次检查权限/预算/风险/确认。

## 四、选择规则

### 硬约束优先于 score

1. 未解决用户请求 / Closure=continue → `conversation_continue`，压过所有自主候选；
2. Closure=undetermined → wait；
3. Closure=close 与未解决请求冲突 → conversation_continue + `closure_inconsistent`；
4. Closure 兼容矩阵：
   - continue → conversation_continue
   - close → advance_goal / interest_exploration / memory_maintenance
   - hold → continue_pending / memory_maintenance
   - undetermined → wait/no_action
5. Goal 必须 `status=active`；paused/terminal 拒绝；
6. Pending 必须 `pending/waiting` 且未过期；done/cancelled/expired 拒绝；
7. 候选 `needsConfirmation`/归属冲突 → 不选，wait；
8. 低置信度（默认 <0.5）、external owner、风险超过 maxRisk、预算不足、allowedActivities 禁止 → 拒绝；
9. 最近成功 Action 同一目标/事项且在 cooldown 内 → 拒绝重复（除非 `newEvidenceSince=true`）；
10. 同类型同目标去重；同优先级按 confidence、candidateId 稳定排序。

优先级（硬）：conversation_continue 100 > continue_pending 80 > advance_goal 70 > interest_exploration 50 > memory_maintenance 40。
