## 三、根因

### 3.1 两个进程并存

```
15:58:43  进程 A（PID 33200）启动，写 lock = 33200
           ↓
           A 的 lock 因为某种原因消失了（exit 钩子没跑 / 被删）
           ↓
19:48:43  进程 B（PID 25984）启动，lock 不存在 → 写 lock = 25984，正常启动
           ↓
          **进程 A 还活着，两个进程并存**
```

### 3.2 为什么会丢消息

**两个进程各自维护一份内存状态，但写同一个文件。**

**发送路径（`src/sender.js:177-185`）**：

```js
const data = await this.onebot.sendText(kind, id, text, {...});
this.#markSent(chatKey, text);
const ts = Date.now();
this.store.appendSelf(chatKey, { text, ts, mid: data?.message_id });   // ← 写 store
this.onSent?.({ chatKey, text, messageId: data?.message_id });          // ← 写日志
```

**两个进程都执行这条路径，但**：

- **进程 A 的 `store` 实例在内存里有一份消息列表**
- **进程 B 的 `store` 实例在内存里有另一份**
- **谁最后落盘谁的赢**（或者 append 时按各自索引）

**结果**：

| 现象 | 解释 |
|---|---|
| QQ 里有 20:13 那条 | **某个进程真的发送了** |
| store 里没有 | **那个进程的 store 没落盘，或者落盘时被另一个进程覆盖** |
| 日志里没有 | **那个进程的 `onSent` 没被调 / 日志被截断** |
| id 连续无空隙 | **两个进程各自计数器，落盘时按自己的索引追加** |

### 3.3 为什么她答成「零食」

**`20:17:08` 那次的上下文（`mw0njmvw` 的 `userPrompt`）**：

```
【已读信息】以下是这个会话最近的聊天记录…
[11-03 11:33] 我：说人话就是
...
```

**注意：已读信息从 11:33 开始**（`contextLimit: 80`）。

**而 16:55 那句「别又拿零食糊弄」在 80 条窗口内**（11:33 之后）。**20:13 那句如果进过 store，应该在** —— **但它没进 store**。

**所以她的上下文里**：

```
✅ 16:55:58  「晚上再吃点热乎的，别又拿零食糊弄」
❌ 20:13     那句话（store 里没有）
```

**她答「别又拿零食糊弄」是唯一可能的答案。**

**这不是幻觉，是数据层缺了那条。**

## 五、根本漏洞（未修）

### 5.1 `instance-lock.js` 的逻辑

```js
// src/instance-lock.js:77
fs.writeFileSync(LOCK_FILE, String(process.pid), { flag: 'wx' });  // 原子创建
// EEXIST → 读 existingPid → pidAlive(existingPid) → 拒绝启动
// 否则删掉残留锁，重试
```

**这个逻辑本身是对的。**

**但它只防「启动时已有活实例」，不防「启动后冒出更早的实例」。**

### 5.2 三个可能的修法

| # | 修法 | 风险 | 我是否推荐 |
|---|---|---|---|
| **1** | 启动后扫一遍，发现比自己早的同程序进程就杀掉 | 可能误杀（用户故意开两个） | ⚠️ **需要机主确认** |
| **2** | OneBot 连接层加互斥（一个数据目录只允许一个 WS） | 复杂，要改 onebot 层 | ⚠️ 改动大 |
| **3** | `messages` store 加进程归属标记，写前检查 | 只是缓解，不解决双发 | ❌ 治标不治本 |

### 5.3 为什么锁会消失

**`registerLockCleanup` 的逻辑**：

```js
process.on('exit', cleanup);   // 只有 exit 才释放锁
for (const sig of ['SIGINT', 'SIGTERM']) {
  process.on(sig, () => { /* 什么都不做，等 exit */ });
}
```

**如果进程被 `Stop-Process -Force`（Windows 的 TerminateProcess）杀掉，`exit` 钩子不会跑** → **锁残留**。

**但 19:48 时锁不存在** —— 说明要么 33200 正常退过（不可能，它还活着），
要么锁被别的东西删了。

**这一层我没查清。**
