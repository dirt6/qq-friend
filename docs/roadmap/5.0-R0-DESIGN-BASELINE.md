# 5.0-R0：长期自主伙伴设计基线

> 版本：v0.1（设计稿，未实施）
> 时间：2026-11-04
> 依据：现有统一伙伴架构、Memory Hub、Goal/Pending/Round/Action、D1-7 报告；SurfCore 只读审查
> 范围：单主伙伴、单 QQ-agent 主进程；不做跨 PROFILE；不实现代码

## 一、总体架构

```
                    ┌────────────────────────────┐
                    │        QQ-agent 主进程      │
                    │   （唯一伙伴主体/单实例）     │
                    └─────────────┬──────────────┘
                                  │
        ┌─────────────────────────┼─────────────────────────┐
        │                         │                         │
   聊天 Orchestrator        自主 Autonomous            其他未来行为
        │                         │                         │
        └───────────────┬─────────┴─────────────┬───────────┘
                        │                       │
                Companion Core（门面/组合根）    │
                        │                       │
   ┌────────────┬───────┼────────┬──────────────┼─────────┐
   │            │       │        │              │         │
 Goal/Pending  Diary  Activity  Memory Hub   ChatStore  DSH Session
   │            │       │        │              │         │
   └────────────┴───────┴────────┴──────────────┴─────────┘
                        │
                  Decision Layer（5.0 新增）
             Purpose / Silence / Selection / Receipt
                  纯逻辑，无 I/O、无模型调用
```

原则：

- 一个伙伴：聊天、自主、未来行为共享同一 Core/状态；
- DSH 是推理工具，不是第二伙伴；
- PROFILE 是运行隔离，不是人格；
- Memory Hub 是统一**读**入口，不是新存储层；
- Goal/Pending/Diary/Activity/ChatStore 各自由领域模块维护；
- 5.0 Decision Layer 只做判断，不直接写存储、不发消息、不调用模型。

## 二、自主活动完整生命周期

```
Trigger（定时/唤醒/聊天后）
  → 1. Observe：读 Core 快照（Goal/Pending/最近 Round/Action/Topic/Activity/预算）
  → 2. Hypothesize：PurposeHypothesis（本轮是否有值得做的事；归属/证据/置信度）
  → 3. Gate：预算、权限、重复、冷却、用户在场/提问
  → 4. Select：延续 Pending / 推进 Goal / 整理记忆 / 浏览兴趣 / 记录发现 / 不行动
  → 5. Plan：本轮 Round 目标、允许 Action、停止条件
  → 6. Act：领域工具/模型（受预算/权限）
  → 7. Record：Round/Action/Activity/记忆（由领域模块写）
  → 8. Share/Silence：A2 判断是否告诉用户、是否留话题、是否结束
  → 9. Close：决策回执；更新 nextWake/冷却；失败则记录可恢复状态
```

每一轮必须允许在第 2/4/8 步结束（不行动/不分享），不把“无产出”判为失败。

## 三、对象关系（严格区分）

| 对象 | 定义 | 时间尺度 | 维护者 | 谁能创建 |
|---|---|---|---|---|
| **Goal** | 长期方向（用户明确/伙伴长期兴趣，需证据） | 周/月 | companion/state | 用户明确或经确认的长期方向；**不得**由一次性请求自动创建 |
| **Pending** | 具体未完成事项 | 天 | companion/state | 用户请求/明确计划；可过期 |
| **Round** | 一次自主活动 | 单次 | autonomous | 每轮一个；允许“无行动 Round” |
| **Action** | Round 中一次执行 | 即时 | autonomous | 受权限/预算；可重试需幂等 |
| **Topic** | 最近聊天话题 | 短期 | 独立 topic 管理 | 聊天提取；不自动变 Goal |
| **PurposeHypothesis** | 本轮目的假设（5.0 新） | 单轮 | 5.0 Decision Layer（内存/回执） | 纯逻辑生成；**不是 Goal** |

关系：

- PurposeHypothesis 引用 Goal/Pending/Topic/Activity 作为证据，但不写它们；
- Round 可关联 0..N Goal/Pending；Action 属于 Round；
- 一次性请求只能产生 Pending/Action，不能自动升级 Goal；
- Topic 不进入 Goal，除非用户明确表达长期方向并经确认。

## 四、Purpose / 意图判断（A1）

### 4.1 输入（只读快照）

- 活跃 Goal（含来源、确认状态、最近进展）；
- Pending（到期/阻塞/可继续）；
- 最近 Round/Action（完成、失败、重复）；
- 最近 Topic（用户最近关注，非长期目标）；
- 近期 Activity（已做过什么、冷却）；
- 可用信息/预算/权限；
- 用户在场状态（聊天中/明确提问/沉默）。

### 4.2 输出（结构化假设）

```json
{
  "hasWorthwhileWork": true,
  "directions": [
    {
      "kind": "continue_pending|advance_goal|memory_maintenance|interest_exploration|record_only|no_action",
      "goalId": "g-...",
      "pendingId": "p-...",
      "owner": "user|partner|inferred|external",
      "epistemic": "explicit|observed|inferred|unknown",
      "evidence": ["..."],
      "confidence": 0.72,
      "value": 0.6,
      "urgency": 0.3,
      "risk": 0.1,
      "expiresAt": "..."
    }
  ],
  "uncertainty": ["..."]
}
```

### 4.3 归属与证据规则

- `owner=user`：用户明确说过的目标/请求，附原文/日期证据；
- `owner=partner`：伙伴自己的长期兴趣，必须有历史依据，不得临时编造；
- `owner=inferred`：从行为推断，**只能低权重**，不得自动写 Goal；
- `owner=external`：视频/群友/第三方内容，**不得**当成用户目标；
- `epistemic=explicit` 优先于 observed/inferred；inferred 不得覆盖 explicit；
- 置信度低于阈值 → 只观察/不行动，不伪造产出；
- 目标归属不明 → `no_action` 或仅记录，不分享为用户目标。

### 4.4 硬规则

- 不因“模型觉得有趣”创建 Goal；
- 不把 Action 当 Goal；
- 不把 Topic 当 Goal；
- 不把外部内容当用户目标；
- 没有值得做的事时输出 `no_action`，这是合法结果。

## 五、沉默权 / 交流收尾（A2）

### 5.1 判断问题

- 是否仍有必要继续交流？
- 是否应该分享发现（C）？
- 是否留自然的下次话题？
- 是否结束本轮？
- 用户是否在明确提问/求助？

### 5.2 规则

- 用户明确提问/求助 → **不得**强行收尾/沉默；优先回应；
- 用户已表达结束/忙 → 允许沉默，不追问；
- 没有新信息/只是重复 → 沉默；
- 有值得分享但不确定是否打扰 → 记录，留到下次聊天（C）；
- 沉默不是失败，不发送“我先不说话”之类消息；
- 收尾后抑制唤醒（`closureSuppressesWake` 语义），但可由用户新消息/明确事件重开；
- 每轮最多一次自然收尾；不连续追问。

### 5.3 输出

```json
{ "shouldContinue": false, "shouldShare": false, "leaveTopic": "…", "reason": "user_busy|no_new_info|closed|question_pending", "suppressWakeUntil": "..." }
```

## 六、活动选择（A3）

候选：

1. 延续可继续 Pending；
2. 推进有证据的长期 Goal；
3. 记忆整理/纠正（D）；
4. 浏览已有兴趣来源（仅已有来源，不无限扩张）；
5. 记录发现（只记录，不分享）；
6. **暂不行动**。

选择必须给出：

- 为何选它；
- 为何不选其他；
- 是否涉及用户目标；
- 是否产生 Action；
- 是否新增 Pending（仅明确具体事项）；
- 是否更新 Goal（仅长期方向，需确认）；
- 是否分享/沉默。

禁止为“每轮有产出”伪造 Action/Round/记忆。

## 七、分享与沉默（C）

分享判断（在 A2 之后）：

- 与用户相关（明确目标/最近话题/请求）；
- 值得打扰（新信息、时效、重要）；
- 非重复（对最近消息/活动去重）；
- 来源可靠（链接/时间/可核验）；
- 适合留到下次聊天（不紧急）；
- 只记录不通知。

默认：**能记录就不打扰**；不催回复；不用连续消息维持活跃；不自动发帖。
用户明确要求“有发现告诉我”时才提高分享优先级。

## 八、记忆读取、写入、纠正、归档（D）

- 读取：Memory Hub/Companion Core；relevance ≠ 可信度；
- 写入：仍由 learned/diary/memory/companion 领域模块负责；Decision Layer 不直接写；
- 纠正：用户明确纠正优先，不能被自动合并覆盖；保留来源/历史；
- 无法恢复的历史纠正继续 `historicalUnresolved`；
- 归档：重要日记不因时间久删除；临时计划可过期；可能变化事实标 `needsReview`；
- 自主活动写入必须带 `source=autonomous, roundId, actionId`，可追溯；
- 重复写入用幂等键；失败不回滚用户已有记忆。

## 九、与聊天活动的协调

- 同一伙伴状态：聊天与自主都读 Core 快照；不建平行状态；
- 聊天进行中：自主默认让位/降频；用户提问时不得被自主收尾打断；
- 聊天产生 Pending/Goal：仅按明确语义写入领域；
- 自主发现可在下次聊天自然提起，不强行插入当前对话；
- 单进程内用一个调度器串行化自主 Round；聊天优先；
- 并发保护：Round/Action 幂等键、文件锁、发送去重。

## 十、模型调用边界与预算

- Decision Layer（Purpose/Silence/Selection/Receipt）**纯逻辑，零模型调用**；
- 只有需要生成内容/工具执行时才调用模型；
- 每轮预算：最大模型调用数、最大 token、最大 Action 数、最大分享数；
- 无值得做的事 → 0 次模型调用；
- 不因“沉默”额外调用模型；
- 预算/频率由配置控制，5.0 不擅自提高；
- 成本记录沿用 token ledger；超预算降级为记录/不行动。

## 十一、异常恢复、幂等、并发

- 每轮 `roundId`；每个 Action `actionId` + 幂等键；
- 崩溃恢复：读取未完成 Round/Action，判断可重试/需人工/放弃；
- 发送消息前持久化意图，发送后标记；重复发送需去重；
- 文件写入用领域锁/原子写；Decision Layer 无状态、可重放；
- 失败记录不得伪造成成功；无法归因标 UNKNOWN；
- 不自动 reset/清理。

## 十三、SurfCore 借鉴边界

- 借鉴 `conversation-closure` 的**沉默权判定思路**（是否仍需交流、收尾后抑制唤醒），不复制正则/代码/依赖；
- 借鉴 `purpose-engine` 的**结构化目标假设 + 谁的目标 + 观察/推断区分**，但改名 PurposeHypothesis，**Purpose ≠ Goal**；
- 不引入 SurfCore 存储/预算/依赖；不假设 DSH 版本兼容。
