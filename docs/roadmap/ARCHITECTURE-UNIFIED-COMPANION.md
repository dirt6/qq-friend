# 架构决策记录：统一 AI 伙伴（Unified Companion）

> 状态：**已批准**（机主 2026-11-03）
> 时间：2026-11-03
> 范围：产品目标、运行主体、记忆边界、PROFILE 定位、路线调整
> 性质：**架构决策 + 文档修订**；本文件不代表以下能力已经实现（见第五、七节）

## 一、决策

**小鲸鱼只有一个核心 AI 伙伴。聊天、自主活动和未来新增行为都是这个伙伴的不同活动方式，共同使用一套记忆和伙伴状态。PROFILE 只是运行隔离机制，不是伙伴身份。跨 PROFILE 记忆共享不属于当前建设范围。**

### 1.1 一个 AI 伙伴，一个统一核心

```text
一个默认 PROFILE
│
└── QQ-agent 主进程
    │
    ├── 聊天行为
    │   ├── 接收 QQ 消息
    │   ├── 理解上下文
    │   ├── 调用模型生成回复
    │   └── 更新伙伴记忆
    │
    ├── 自主行为
    │   ├── 空闲时间活动
    │   ├── 兴趣探索
    │   ├── 整理记忆
    │   ├── 继续未完成事项
    │   └── 记录活动结果
    │
    ├── 未来扩展行为
    │   ├── 主动分享
    │   ├── 自主学习
    │   └── 其他后续能力
    │
    └── 统一伙伴核心
        ├── 人设
        ├── Memory Hub
        ├── 日记
        ├── Goal
        ├── Pending
        ├── Action / Round
        ├── 兴趣与偏好
        ├── 历史交流
        └── 其他伙伴状态
```

**以上行为共享同一套伙伴状态和记忆。**

### 1.2 QQ-agent 与 DSH 的区分

- **QQ-agent 是长期运行的伙伴主进程**。
- **DSH 是模型推理工具**，需要思考时由 QQ-agent 调用；DSH 的推理子进程**不代表另一个 AI 伙伴**。
- 聊天和自主活动可以分别触发 DSH 调用，但都属于同一个伙伴。
- 不要求聊天与自主活动同时运行两个长期驻留的 AI 进程。
- **当前 DSH 调用方式和 Session 机制不在本次修改范围内**；后续是否调整，由统一伙伴核心架构决定。

### 1.3 所有行为共享统一记忆

1. 统一使用 **Memory Hub** 作为记忆访问入口。
2. 不允许每个行为自行维护一套互不关联的长期记忆。
3. 聊天产生的重要信息可以被自主活动检索。
4. 自主活动发现的内容可以被聊天检索。
5. 自主活动产生的日记、Goal、Pending、Action 等信息，聊天也可以访问。
6. 不同活动不得绕过现有记忆可信度、纠正状态和写入规则。
7. 统一伙伴核心应当允许未来新增行为，而不需要重新建立记忆体系。

> 共享记忆 **不意味着**所有内容每轮都注入模型上下文。仍由 Memory Hub 根据相关性、可信度、时间和使用场景决定检索内容。

### 1.4 PROFILE 的定位

PROFILE 是**运行实例的隔离配置**，不是 AI 伙伴的人格身份。

- 当前项目只以默认 PROFILE 作为主要伙伴运行环境。
- 不建设跨 PROFILE 记忆共享。
- 不建设多个 AI 伙伴之间的记忆同步。
- 不迁移或合并不同 PROFILE 的生产数据。
- 不为了 PROFILE=2 提前引入分布式记忆、跨实例同步或共享存储。
- **保留现有多 PROFILE 安全隔离能力**，不因本次决策删除 R8-0 的成果。

## 二、现有工作的定位（不得重复建设）

| 已有工作 | 在统一伙伴架构中的定位 |
|---|---|
| R3 记忆元数据 | 记忆来源、类型和纠正信息 |
| R4 Memory Hub | 统一记忆访问入口 |
| R5 日记元数据写入 | 日记写入安全与元数据管理 |
| R8-A 记忆调查 | 生产数据现状和治理问题基线 |
| R8-B 三态纠正状态 | `clear / unresolved / unknown` 纠正状态管理 |
| R8-0 A1–A3 | PROFILE 数据目录和单实例启动安全 |

这些成果**服务于单个 AI 伙伴的长期记忆体系**，不得被重新解释成多 AI 共享记忆的前置工程。

## 三、路线调整

### 3.1 当前阶段：完成统一架构定义（本次）

1. 本 ADR 作为正式架构决策写入项目文档。
2. 修订 4.0–5.0 路线文档（`ROADMAP-4.0-5.0.md`）。
3. 修订记忆数据模型（`MEMORY-DATA-MODEL.md`）的适用范围。
4. 检查 `MIGRATION-PLAN.md` 与 `IMPLEMENTATION-BATCHES*.md` 是否有冲突内容。
5. **R8-M 跨 PROFILE 共享记忆计划**：仓库中未找到该计划（无 `R8-M` 文档/条目），无需删除；本 ADR 明确"不建设"。
6. **保留 R8-C**（记忆治理：可信度、晋升、归档、检索），不取消。

### 3.2 后续阶段：推进统一伙伴核心

> 重点不是让聊天和自主活动共享一份文件，而是确保它们共享**同一套伙伴状态、记忆规则和生命周期**。

**第一步：统一入口检查**（只读）

调查聊天、自主活动和现有插件分别如何访问：

- Memory Hub
- Goal / Pending
- 日记
- Activity History
- 伙伴人设和状态

识别绕过统一入口的地方。

**第二步：统一状态与生命周期**

明确聊天和自主活动如何共同维护：

- Goal：长期方向
- Pending：未完成事项
- Round：一次自主活动
- Action：具体执行
- Topic：近期聊天话题

沿用已有概念约束，不重新设计一套相似的数据模型。

**第三步：推进记忆治理**

继续 R8-C，处理记忆可信度、晋升、归档和检索策略。

- 不得自动覆盖用户纠正过的内容；
- 不得将未知纠正状态当成已解决。

**第四步：支持未来行为扩展**

未来新增行为统一接入伙伴核心，不得自行建立平行的长期记忆。

## 四、当前实现的真实状态（只读检查结论）

> 以下来自代码只读检查（2026-11-03），**不代表已接入**。

| 行为 | 实际记忆访问路径 | 是否经 Memory Hub |
|---|---|---|
| 聊天 | `MemoryStore`（`memory.js`）读群友印象 → `prompt.js`；`learned.js` 写入经验；`companion/state.js` 读伙伴状态；聊天 `store.js` | ❌ 未接入 |
| 自主活动 | 直接 import `companion/state.js`、`diary/index.js`、读 `data/messages/*.json`；日记直接写文件 | ❌ 未接入 |
| 插件（qqzone / qq-self 等） | 通过工具上下文（`ctx.store` / `ctx.memory`）与各自逻辑 | ❌ 未接入 |
| Memory Hub | `src/memory-hub/index.js` 有只读 `search/get`，但**只有测试调用**，业务代码未使用 | — |
| 日记写入 | `memory-hub/diary-write.js` 是统一写入口，但 `plugins/autonomous` 仍直接 `writeDiary`（`diary/index.js`） | 部分绕开 |

**结论**：Memory Hub 目前是"已建好、未接线"的读取层；统一记忆入口是后续第一步工作，不是已完成状态。
