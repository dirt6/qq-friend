# 5.0 空闲 Goal/Purpose 循环

> 时间：2026-11-05
> 状态：已接入 think；A1/A2/A3 真正参与每一轮空闲决策

## 一、为什么改

之前的空闲 `think` 是「模型自由挑一个动作」，A1（Purpose）、A2（Closure）、A3（Activity）
虽然写好了，只在 G1 只读演练里用过，没有参与真实空闲循环。表现就是：
每次醒来都从零开始想，长期方向/没做完的事/她自己的兴趣不会主动被带回来。

## 二、现在的流程

```text
醒来（3h 窗口 / 她自己约的时间）
  → 读快照：active/paused Goal + 未结算 Pending + 最近聊天
  → A2 Closure：主人还在等回应？→ 是则本轮不自主（只记账）
  → A1 Purpose：目标 / 待办 / 她自己的兴趣 → 候选
  → A3 Activity：按 close 与 hold 各算一次，取优先级更高者
      close → 推进长期方向 / 兴趣 / 整理
      hold  → 继续未完成事项 / 整理
  → 有方向：受限 think（只允许该方向对应的动作）
  → 没方向：从本子找一件她自己的兴趣；再没有才回到自由 think
  → 执行（浏览 / 整理 / 写日记 / 写本子 / 分享 / 聊天 / 睡）
  → 记账（data/5.0-goal-cycle.json），下一轮作为上下文与 6h 冷却依据
```

### 动作

| 动作 | 含义 | 边界 |
|---|---|---|
| `browse` | 逛小黑盒（只读） | 不发任何内容 |
| `diary` | 整理已有日记（只读原文） | 不改原文 |
| `write_diary` | 把这一轮看到/想到的写进当天日记 | 经 `diary.write`，格式与日记技能一致；没看到内容只写真实想法 |
| `write_notebook` | 写进她自己的本子 | 只有她自己看；不自动分享 |
| `share` | 分享一条到当前聊天 | 静默时段不可用；去重 |
| `chat` | 主动找老大说话 | 静默时段不可用；去重 |
| `comment` / `reply` | B站评论/回复 | 只在自由 think 里；仍需 API 且受静默/去重保护 |
| `sleep` / `none` | 睡一会儿 / 什么都不做 | 合法选择，不推进、不占冷却 |

### 静默时段（00:00–08:00）

- **可以睡，但不是必须睡**：静默时段照常跑 `think`；
- 只允许不打扰人的动作（浏览、整理、写日记、写本子、睡、不做）；
- 分享/聊天/评论在静默时既不提供也不会发（`idle-actions` 仍二次拦截）。

### 定时醒来

- 30–1440 分钟范围内她可以自己约；
- **取消每日改期次数上限**（原 4 次/天），`counts` 只用于观察；
- 保留最短 30 分钟，避免醒来风暴；新约覆盖旧约。

### 停止条件（R8）

- 同一方向（goal / pending / 兴趣标题）**连续 3 轮没有进展** → 暂停 24 小时，不再每 3 小时重试；
- 「有进展」= 该轮动作真的做成了（浏览/整理/写日记/写本子/分享/聊天成功）；
- **成功一次就清零**，不需要人工解除；24 小时后自动允许再试；
- 只影响本轮选择，**不改 Goal/Pending 状态**（是否放弃由主人决定）；
- 暂停与其他方向互不连坐。

### 计划 → 下一步（R8-C）

- 每轮 think 可以输出 `next`（一句话的下一步），写进运行账本；
- 下一轮 prompt 会带回来（`（下一步：…）`），形成“计划 → 执行 → 记录 → 下次接着做”的闭环；
- `next` 只是她自己的备忘，不是 Goal，也不写 Memory Hub。

### 指标与治理（R9 / R10）

- `GET /api/5.0/metrics`：近 7 天醒来轮次、主动聊天、分享、评论/回复、写日记/本子、安静跳过、模型调用与估算成本；
- `GET /api/memory/governance`：经验状态分布、被纠正条数、来源天数、待办状态/过期数、Hub 统计；**只读、不返回正文**；
- 失败/空数据都返回可读的 0，不报假成功。

### 面板

`空闲时间` 页已改为读 5.0 真实状态（`GET /api/autonomous` 的 `v5` 字段）：

- 状态 / 上次醒来 / 下次醒来（**标注「系统周期」或「她自己设的」**）；
- 当前在追的方向（5.0 Goal）、她的待办、她自己约的醒来；
- 最近的醒来记录（动作 / 结果 / 原因）；
- 旧 `autonomous.json` 记录折叠在「旧插件记录」里，只作参考，不再作为当前目标来源。

## 三、与旧实现的关系（都可读，未被删除）

5.0 之前的空闲/定时醒实现在：

- `plugins/autonomous/index.js`（约 110KB：醒来节奏、意图阶段、planner、预算、写日记、自设醒来、安静时段）；
- `plugins/autonomous/lib/*`（planner / goal-judge / state / budget / 收件箱等）；
- `doc/自主活动-2.1方案.md`、`doc/接手-prompt.md` 的空闲章节。

这些文件**仍然存在、可读**，只是插件保持 disabled（避免重新引入全量自动循环）。
5.0 的空闲是单伙伴、低权限的独立实现（`src/idle-*.js`），只移植了其中安全的语义：

| 旧实现 | 5.0 |
|---|---|
| `appendDiaryLine` → `diary.write` | `write_diary` 复用同一写入口 |
| 自设醒来（30–1440 分钟，每天 4 次） | 保留范围，取消次数上限 |
| 安静时段分享只记录不发送 | `idle-actions` 的 `quiet_hours` 拦截 |
| planner / goal-judge / 全量自动评论 | **不移植**；改为 A1/A2/A3 + 受限动作 |

## 四、安全边界

- 不创建/修改 Goal、Pending（只读快照）；不替主人改方向；
- 不建第二套记忆；账本 `data/5.0-goal-cycle.json` 是运行记录，不是记忆；
- 主人还在等回应（未解决请求/提问未答）时不自主行动；
- 无证据的自主 Goal、归属不明的 Pending 一律不执行；
- 公开动作仍走预览/确认/去重/静默，失败不重发。
