# 5.0 B站 / 小黑盒 @ 处理（空闲或机主叫她才查）— 开工单

> 决定时间：2026-11-06 00:20，00:31 修订（机主）
> 状态：**已定，明天实现**；今天不改代码。
>
> 修订点：**不做 10–15 分钟轮询**；只在「空闲窗口」或「机主叫她」时查。
> 空闲时她也可以主动评论 @ 她的视频。小黑盒同样处理（但评论只能走浏览器手动确认）。

## 一、触发方式（替代轮询）

1. **空闲 think**（每 3 小时，`idle-scheduler`）：
   - 读 B站收件箱（`bili_inbox`）与小黑盒通知（`xhh_read notify`）；
   - 有新的 @ / 回复她的 → 读内容 → 决定回复/评论（B站自动发）。
2. **机主叫她**（聊天里说「看看谁 @ 我了」）：她当场查、当场处理。
3. 不新建独立定时器，不 10–15 分钟轮询。

## 二、B站

| 情况 | 动作 |
|---|---|
| 有人 @ 她 / 回复她 | 读视频标题、简介、热评 → 写回复 → `bili_comment` 带 `replyTo`/`root` 自动发 |
| **@ 她的视频**（不是回复某条评论） | 空闲时可以**主动发一条顶层评论**（评论视频本身），不用等回复 |
| **别人的视频（没 @ 她）** | 空闲时可以主动浏览/挑选，读详情+热评后发顶层评论；**可以在评论里 @ 主人**（`mention=owner`，解析为「泥土如是说」） |
| 读不到内容 | 不编造，记 skipped |

## 三、小黑盒

- 空闲/叫她时读 `xhh_read notify`（回复/@）；
- 发现 @ → 把「谁 @ 了她、帖子标题/链接」发到 QQ 通知；
- **评论仍只能走浏览器**（API 被拦、有头 Edge 会抢前台）：生成草稿 → 机主确认后在浏览器发送；
- 不做小黑盒全自动评论。

## 四、去重 / 静默 / 失败

- 同一条评论/rpid 只回一次；同一视频 2 小时内最多 1 条；
- 00:00–08:00 不发（可延后或跳过并记账）；
- 失败/UNKNOWN 不重发；
- **可以主动评论别人的视频、也可以在评论里 @ 主人**；但受现有评论限频（每小时 3 条）、去重与静默约束，不刷屏；
- 不回复自己、不点赞；评论内容必须有依据（标题/简介/热评），不假装看过视频本体。
