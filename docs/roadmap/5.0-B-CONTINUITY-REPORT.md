## 一、实现

输入：Goal/Pending/Round/Action/Topic、`now`、`tickId`、`processedTicks`、`processedKeys`、`newEvidence`、`limits.maxRetries`。

输出：

```js
{
  ok, duplicateTick,
  context: { activeGoalIds, inactiveGoalIds, activePendingIds, expiredPendingIds,
             terminalPendingIds, lastRoundId, lastActionId, unfinishedActionIds, topicIds },
  resumeCandidates: [{kind, sourceType, sourceId, title, reason, idempotencyKey,
                      requiresConfirmation, risk, roundId}],
  blocked: [{kind, sourceId/actionId, reason, idempotencyKey}],
  completedItems, uncertainties, diagnostics
}
```

`resumeCandidates.kind`：continue_pending / advance_goal / retry_action。B 只建议，不执行。

## 二、规则

- 只按稳定 ID 关联；不按标题合并，不建第二套任务系统；
- Goal 只 active；paused/terminal 不复活；
- Pending 只 pending/waiting 且未过期；done/cancelled/expired 不进入；
- Action 成功 → completedItems，Pending 不重复；
- Action failed + safeToRetry + attempts < maxRetries → retry_action；
- Action failed 不可安全重试 / 超限 → blocked；
- Action started/unknown → blocked `outcome_unknown_*`，**不盲目重试**；
- authorized/decision_recorded 未执行 → blocked `not_started_requires_execution_authorization`，不当作 unknown；
- 旧 Action 缺关联 ID → `legacy_missing_link`，保守阻塞；
- `processedKeys` → already_processed；`newEvidence` 命中才允许继续；
- 重复 tick → `duplicateTick:true`，不产生候选；
- 相似 Pending → 按 ID 分开，标 `similar_pending_items`。
