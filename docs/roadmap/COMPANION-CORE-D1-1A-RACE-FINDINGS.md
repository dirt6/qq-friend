# D1-1A 补充验证：rename 认领竞态与锁身份（证伪）

> 时间：2026-11-03
> 性质：只读隔离实验（临时目录）
> 结论：**原推荐方案（wx + rename 认领）不满足安全要求**，存在确定的 TOCTOU 双持锁路径
> 实验：`scripts/experiments/d11a-lock/race.mjs`（5 次重复，结果一致）

---

## 一、被测协议（原方案）

```
进临界区：wx 成功（唯一条件）
陈旧：pid 不活 或 at > 30s
回收：rename(lock → lock.stale.<pid>.<ts>) 认领 → 重新 wx
释放：校验 pid == 自己 → unlink
```

## 二、Barrier 实验设计

| 角色 | 动作 |
|---|---|
| A（回收者） | 读到 L1（token=L1，pid 已死）→ 判定过期 → **暂停 800ms**（模拟检查与 rename 之间的调度间隙）→ `rename(lock → claimedA)` → wx 自己的锁 → 临界区 |
| B（另一合法认领者） | 等 200ms → `rename(lock → claimedB)`（合法认领 L1）→ wx 创建活锁 **L2（token=B）** → 进入临界区并持锁 1500ms |

检查项：A 是否移动了 L2；B 是否仍认为持锁；两者临界区是否重叠。

## 三、实验结果（5/5 一致，无偶然）

| 次 | A 检查到 | A 移走 | B 的锁 | 临界区重叠 | A 移动活锁 | 最终计数 |
|---|---|---|---|---|---|---|
| 1 | L1 | **B** | L2 | **是** | **是** | 1 |
| 2 | L1 | **B** | L2 | **是** | **是** | 1 |
| 3 | L1 | **B** | L2 | **是** | **是** | 1 |
| 4 | L1 | **B** | L2 | **是** | **是** | 1 |
| 5 | L1 | **B** | L2 | **是** | **是** | 1 |

**时间线（单次运行）**：

```
0ms    A 读到 L1（过期）→ 暂停
200ms  B 认领 L1，创建 L2（token=B），进入临界区（持锁到 1700ms）
800ms  A 恢复，rename(lock=L2 → claimedA)  ← 把 B 的活锁移走
800ms  A wx 成功（lock 路径已空），进入临界区
800ms  两个进程同时持锁 → 双持
1700ms B 退出临界区并写文件（读的是 200ms 的旧值）
       → 覆盖 A 在 800ms 的写入（丢更新，final=1）
```

## 四、结论：协议存在无法用"再检查一次"根治的竞态

- 两个合法进程都执行"检查过期 → rename 认领"时，A 的 rename 会命中 B **新建的活锁**；
- 事后校验（读 claimed 内容发现是 B）**已经造成事实**：B 的锁路径已被移走，B 仍以为自己持锁并继续临界区；
- 用户态文件系统没有 **compare-and-rename**（条件移动）；"检查 → 移动"之间的窗口不可消除；
- 因此 **不能证明"回收操作不会移动其他进程新建的活锁"**，按验收标准 → **该方案不合格**。

## 五、补充检查结论

| 检查项 | 结论 |
|---|---|
| 固定 30s 上限判断 PID 复用 | ❌ 不可靠：30s 内复用/长时间任务都会误判；且上限不解决上面的窗口问题 |
| lock timeout / stale 判定 / owner 身份 | 三者语义不同，但本协议把它们混在"wx + 内容"里；owner 身份无法阻止误移动 |
| stale 归档目标覆盖 | `claimed` 路径含 pid+时间戳，理论上不覆盖；但 Windows `rename` 到已存在目标会失败——本次未触发，**未完全验证** |
| rename 失败 / 中断后的恢复 | A rename 失败会重试；但**成功误移动**的情况无法恢复（B 的锁已不在原路径） |

## 六、重新评估选项（D1-1B 前必须选定）

| 方案 | 安全性 | 可行性 | 备注 |
|---|---|---|---|
| **OS 原生锁（LockFileEx / 命名互斥）** | 高（内核保证，进程退出自动释放，无 stale 回收） | 需 native addon + Electron ABI 编译，**需授权安装/验证** | 最彻底 |
| **端口锁（bind 127.0.0.1 端口）** | 高（OS 独占 bind；进程退出自动释放；无 stale 文件） | 纯 Node、零依赖，**待实验**（端口冲突/防火墙/映射范围） | 推荐下一步验证 |
| **不可回收锁 + 启动清理** | 中（运行期无双持；崩溃残留靠启动清理） | 纯 Node；需定义"何时清理安全"（单实例守门后） | 次选 |
| 单写入者（收敛到主进程） | 高（进程内队列） | 需把外部写者收编/禁止；工程量大 | 长期方向 |
| 原 wx + rename 认领 | **低（已证伪）** | — | **否决** |

## 七、下一步

- 若端口锁不满足（防火墙/端口映射问题），再评估 native 方案（需授权安装）。
