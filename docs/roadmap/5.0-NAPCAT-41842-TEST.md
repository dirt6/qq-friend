# NapCat 4.18.42 升级尝试（2026-11-05）

## 目的

QQ 自动更新到 9.9.37 后，SnowLuma 1.14.22 偶发 `wrapper.node` 崩溃；项目历史协议端是 NapCat，
所以尝试把 `napcat/shell` 从 4.18.37 升到最新 **4.18.42**（`NapCat.Shell.Windows.Node.zip`，118MB）。

## 做了什么

1. 下载并解压到 `napcat/shell.new`，结构与旧版一致：
   - 根：`node.exe` / `wrapper.node` / `index.js` / `QQNT.dll` / `config.json`
   - `napcat/`：`NapCatWinBootMain.exe` / `NapCatWinBootHook.dll` / `qqnt.json` / `napcat.mjs` / `launcher.bat`
2. 备份旧 shell 为 `napcat/shell.bak-4.18.37`；
3. 新包替换为 `napcat/shell`；
4. 迁移旧 OneBot 配置：`onebot11.json`、`onebot11_2029382488.json`（端口 3000/3001、令牌不变）；
5. 停 SnowLuma + 停 QQ，然后用 `/api/ops/napcat/start` 提权启动 NapCat。

## 结果：失败

- `NapCatWinBootMain.exe` 拉起 QQ 后退出；
- QQ.exe 停在 **37MB**、无窗口进展；
- **6099（WebUI）/ 3000 / 3001 都没有监听**；
- `napcat/shell/napcat/logs` 没有生成日志；
- 进程是提权启动的，普通 `taskkill` 被拒绝（需要管理员）。

判断：NapCat 4.18.42 的 `qqnt.json` 仍是 `9.9.22-40990` 基线，**没有适配 QQ 9.9.37**，
注入卡住，起不来 OneBot。

## 回滚

- 杀掉卡住的 QQ（由系统/管理员清理）；
- 重新启动 QQ（`D:\NTQQ` + `qq-portable-data`）与 SnowLuma；
- `GET /api/status`：`onebot.connected = true`，账号 2029382488，生产恢复。

## 结论

1. 当前**继续用 SnowLuma 1.14.22**（能连上，但偶发 `wrapper.node` 崩溃）；
2. NapCat 4.18.42 对 QQ 9.9.37 不可用；旧版 4.18.37 备份保留（`napcat/shell.bak-4.18.37`）；
3. 等 NapCat 发布适配 9.9.37 的版本，或把 QQ 降到它能识别的版本后再切换；
4. SnowLuma 没有公开更新渠道（`@snowluma/runtime` 私有包），短期无法靠升级解决崩溃。
