## 一、Token 方案（已解决架构阻断）

### 关键发现

- G1 原读 `getConfig().server.token`；该 token 是**全局 API 认证**；
- UI 固定发送 `x-console-token: qq-agent-console`（静态 marker），若设置随机 `server.token`，**现有 UI 全部 401**；
- 因此不能为 G1 覆盖全局 token。

### 实现

- G1 改为独立 token 文件：`data/5.0-g1/token`；
- 路由使用 `x-g1-token`，不读取全局 `server.token`；
- `src/g1-service.js` 每次请求读取 token 文件，长度 <32 或缺失 → 拒绝；
- timingSafeEqual；token 不进 config/URL/日志/报告；
- 全局 `server.token` 保持空，UI/现有 API 行为不变。

### 生成/验证

- `scripts/5.0-e5-g1-token.mjs`：`crypto.randomBytes(32).toString('base64url')`（43 字符）；
- 默认 dry-run；`--apply` 才写；已存在拒绝覆盖；不打印明文；mode 0600；
- 隔离测试：生成 43 字符、dry-run 不写、已存在拒绝；
- G1 主进程专项：无文件 401、错误 token 401、URL token 401、正确 token 通过；
- 生产 token 文件**未创建**，全局 token 未改。

### 轮换/备份

- 轮换：维护窗口替换 `data/5.0-g1/token`（先备份旧文件到受 ACL 保护目录）；服务每请求读取，旧 token 立即失效；UI 不受影响；
- 备份：token 不应进 Git/普通配置；部署包不包含 token。

## 二、ACL 阻断（管理员演练 PASS）

当前生产 `data/5.0-g1` ACL：

- `Authenticated Users: Modify`、`Users: ReadAndExecute`、Everyone deny delete、两个未知 SID write；
- **不满足最小权限**；未修改。

目标最小矩阵：

| 账户 | 权限 |
|---|---|
| `LAPTOP-HANXC102\lenovo`（Electron 运行账户） | Modify（创建/写入审计/token） |
| `BUILTIN\Administrators` | FullControl |
| `NT AUTHORITY\SYSTEM` | FullControl |
| `Authenticated Users` / `Users` | 移除 Modify/写；不授予不必要权限 |

隔离演练（临时目录）：

- `icacls /inheritance:r` + 精确 grant 后，只有当前用户/Admin/SYSTEM；当前用户可创建/写入审计文件；
- 管理员会话 `scripts/5.0-e5-acl-drill.ps1`：DACL/Owner/Group/SACL 逐项一致（`daclEqual=true/saclEqual=true`），最小权限期间无宽写 ACE（`minimalBroadWrite=false`），恢复后原始宽 ACE 回来；
- 非授权账户真实写入：创建临时标准用户后，`Start-Process -Credential` 子进程未能启动（系统策略），无法执行真实写入；标 `UNVERIFIED_CHILD_NOT_STARTED`；ACL 矩阵显示最小权限期间无 Users/Authenticated Users 写 ACE。
- 结论：**最小权限修改/写入 PASS；精确 ACL 回滚 PASS（管理员）；非授权账户实际写入 UNVERIFIED**。
