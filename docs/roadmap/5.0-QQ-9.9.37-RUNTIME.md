# QQ 9.9.37 自动更新后的运行修复（2026-11-05）

## 现象

- 22:12 QQ 自动更新，安装到 `D:\NTQQ`（9.9.37-54395）。
- 项目便携 QQ（`runtime/qq-portable`，9.9.33-51802）启动时弹：
  「文件已损坏，请重新安装QQ。」
- 启动日志在 `[preload]` 之后退出，退出码 `2147483651`（0x80000003）。

## 真正原因

QQ 9.9.37 会校验「运行路径必须等于安装路径」：

- 直接复制 `D:\NTQQ` 到 `E:\dsh\QQ-agent\runtime\qq-portable` → 启动仍退出；
- 用 junction 指过去（进程路径仍是 E:）→ 同样退出；
- 只有从 `D:\NTQQ` 本身启动、用独立 `--user-data-dir` 才正常。

删除 `runtime/.cache/QQ_portable.zip`（setup 的安装包缓存）**不是原因**；那个文件与已解压的运
行文件无关。

## 修复

1. `data/config.json` 增加（未跟踪文件，不进 Git）：
   ```json
   "runtime": { "qqPortableDir": "D:/NTQQ" }
   ```
2. `src/app.js` 的 `qqPortableDir()` 优先读 `runtime.qqPortableDir`，默认仍是
   `runtime/qq-portable`（旧机器/旧安装行为不变）。
3. QQ 数据仍然独立：`runtime/qq-portable-data`（不碰日常 QQ 的数据目录）。
4. `snowluma/index.mjs` 版本声明对齐：
   - `LIST_QQ_VERSION` → `9.9.37-54395`
   - `BUILD_VERSION_SHORT` → `9.9.37`
   - 原文件备份在 `snowluma/index.mjs.orig`。
5. 删除已无用的 junction 与 `qq-portable.bak-9.9.33`（9.9.33 已无法启动）。

## 验证

- QQ 从 `D:\NTQQ` 启动（进程存活）；
- SnowLuma 正常启动并 hook；
- `GET /api/status`：`onebot.connected = true`，账号 `2029382488`。

## 注意

- 便携 QQ 现在与日常 QQ **共用程序文件**（不同 user-data-dir）。如果日常 QQ 同时运行，
  可能受 QQ 多开限制；需要彻底隔离时，应等腾讯重新提供可复制的安装包。
- 以后 QQ 再自动更新，只需把 `runtime.qqPortableDir` 指向新安装目录，并同步
  SnowLuma 的两个版本字符串。
