## 一、三个检查

### 1. 并发一致性 ✅

`test/phase1-acceptance-test.mjs` 第①②节，用**真实的 `state.js`**（不是模拟）跑三写者场景：

| 场景 | 结果 |
|---|---|
| A 写 seen、B 写 seen、C 写 pendingNextStep，三者都基于同一份旧快照 | seen 两边都在、history 在、pendingNextStep 是 C 的 |
| 面板先写 `pendingNextStep`、自主后写（快照里该字段为空） | **第一次跑失败了** — 见下 |

#### 发现的缺陷：标量覆盖会误伤别人刚改的状态

```
面板写：pendingNextStep = { topic: '面板的计划' }
自主写：st 里 pendingNextStep 还是 ''（它的快照）
结果：  pendingNextStep = ''     ← 面板的修改被吃掉
```

原来的合并只对 `seen/history/shares` 做增量，标量一律 `Object.assign(cur, state)`。

**修复**：`readState` 时记一份 `__base`（非枚举的 JSON 快照），`writeState` 做字段级 diff ——
只有「本轮真正改过」的字段才覆盖，没碰过的保留锁内别人写的值。

修复后：面板的 `pendingNextStep` 和自主的 `selfWake` **同时都在**。

这是 `阶段1.2-复查报告` 里写过的口径，`readDay` 会明确返回 `cost: null + costAccurate: false`，不假装精确。
