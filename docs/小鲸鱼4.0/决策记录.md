## 0. 总原则

1. **独立 Session，共享记忆，同一个人格。**
   聊天与独处各自有连续性；上午聊天形成的想法，下午能自己探索，晚上能接着讨论；换 Session 不等于失忆。
2. **Memory Hub 不是第三套记忆。**
   它是现有记忆（日记、经验、印象、活动、聊天记录）的**统一入口**，不是复制一份再让各模块各自维护。
3. **同一字段只能有一个真正的写入者。**
   迁移期允许旧字段只读兼容，不允许双写。
4. **不为了统一而牺牲体验。**
   Go/No-Go 不通过时，允许 Autonomous 暂留旧 API，但必须共享 Companion State 与 Memory Hub。

## 1. 已拍板的四项

### D1 · 自主活动模型入口

**结论：全部走 DSH。先测延迟，再优化进程复用；不因延迟直接回退旧 API。**

分两步：

1. **先测量，不急着优化**

   | 指标 | 记录内容 |
   |---|---|
   | 进程启动 | spawn 耗时 |
   | 模型响应 | 首 token、完整响应耗时 |
   | 单次调用 | P50、P95 |
   | 整轮活动 | 2~6 次调用总耗时 |
   | 异常 | 超时、进程退出、Session 恢复失败 |

2. **研究同一轮复用进程**：自主活动唤醒 → 启动 DSH 工作进程 → intent → decision → 工具结果 → 继续思考 → 结束 → 关闭。
   前提是验证 DSH CLI 是否支持同一进程连续处理多个请求；**不支持就不能假设可复用**。

**验收阈值（工程建议值，非现有性能数据）**：

| 单轮 P95 | 处理 |
|---|---|
| ≤ 60 s | 可以接受，继续迁移 |
| 60~120 s | 需要优化后再继续 |
| > 120 s | 暂停全面迁移，先解决调用架构（No-Go） |

30 分钟活动窗口保持不变。

### D2 · Companion State 与 autonomous.json 的归属

**结论：迁移跨模式状态，保留运行状态；按数据职责划分，不做整体搬迁。**

| 数据 | 最终归属 |
|---|---|
| currentGoal | Companion State |
| pendingNextStep | Companion State |
| 当前话题 | Companion State |
| 跨模式计划 | Companion State |
| selfWake | Autonomous Scheduler |
| nextWakeAt | Autonomous Scheduler |
| 活动历史 | autonomous.json |
| 活动执行结果 | autonomous.json |
| 活动预算 | Autonomous |
| 模型调用统计 | 统一 Token 账本 |

迁移规则：

- `pendingNextStep` 迁移后，**Companion State 是唯一真源**；Autonomous 只读。
- 旧版 `autonomous.json` 保留只读兼容字段，迁移完成后再移除。
- 不允许两个地方分别修改同一字段。

### D3 · 日记写入口归一

**结论：完全同意。这是 Memory Hub 开发前的必要条件。**

保留：Markdown 格式、原目录、日期文件、重要等级（一般/重要/非常重要）、心情字段、全部历史日记。
只统一写入入口。

```
diary/
├── diary.js
├── writer.js
├── reader.js
└── lock.js
```

统一接口：

```js
await diary.write({
  source: "autonomous",
  content: "...",
  importance: "important",
  mood: "开心"
});
```

三个旧入口逐步改为调用：`diary 技能` / `autonomous` / `qq-tools` → **Diary Writer** → Markdown。

必须增加：并发写入保护、失败重试、防重复记录、写入结果确认、保留原始记录。
**不把日记变成数据库，不把 Markdown 转成 JSON。**

### D4 · Session 轮换

**结论：需要自动轮换，但不清空、不删除旧会话。**

| 状态 | 处理 |
|---|---|
| 正常使用 | 继续当前 Session |
| 上下文使用率 > 70% | 准备摘要与轮换 |
| > 80% | 优先新 Session |
| 上下文质量明显下降 | 提前轮换 |
| Session 损坏 | 从记忆中心恢复 |

轮换流程：旧 Session → 生成阶段性摘要 → 写入 Memory Hub → 创建新 Session → 注入核心人格与相关记忆 → 继续聊天。
旧 Session 保留；**摘要只用于恢复，不替代原始聊天记录**；Chat 与 Autonomous 分别管理轮换。

## 2. 用户补充的原则（写入验收）

- Memory Hub 不得复制出"第二份日记/经验/活动记录"；只做统一读写入口。
- 聊天与独处是两个上下文，但必须是同一个人格、同一份记忆。
- 她不必把所有思考都告诉老大，但不会因为换 Session 就忘记自己经历过的事。

## 3. 已拍板的三项（D5~D7）

### D5 · 事件日志保留与存储（Q1：A+B + 压缩与磁盘保护）

**保留规则**

- 未处理事件永久保留，直到成功消费。
- 已处理事件保留 90 天；超过 90 天按月归档；归档文件长期保留，不自动删除。
- 按 `processedAt` 判断归档资格，不按创建时间直接删除。
- 归档前校验完整性：事件 ID 不丢失、不重复。

**归档压缩**

- 归档用 gzip（`.ndjson.gz`），按月组织。
- 查询时按需解压，不长期加载内存。
- 保留原始事件内容与 `eventId`，不因压缩改变语义。

```
companion-events/
  active.ndjson
  archive/
    2026-10.ndjson.gz
    2026-11.ndjson.gz
```

**内存与读取**

- 启动只读当前状态快照与必要的未处理事件。
- 不在每轮启动时加载全部历史事件。
- 历史归档仅在 Memory Hub 检索时按需读取。
- 索引与缓存设容量上限；定期清理过期缓存，不清理原始历史。

**磁盘保护**

- 每月统计归档总大小：>500 MB 提醒；>1 GB 暂停自动归档扩张并提醒检查。
- 不自动删除未处理事件；不自动删除唯一原始记录。
- 超阈值时优先检查重复记录、压缩效果、索引占用。
- 阈值为初始建议值，支持配置调整。

**核心原则：永久保留原始事件，不永久加载原始事件。**

### D6 · 控制面板写权限（Q2：C 方案）

- 保留 `bot` / `panel` 运维权限。
- 保留表情库管理权限。
- 记忆类写操作统一迁移至 Memory Hub。
- 面板只读展示日记、经验、印象、活动历史。
- 修改记忆走 Memory Hub 提供的授权接口。
- 绘画作品删除等非记忆操作可保留，但必须记录操作事件。

### D7 · 旧 API 回退策略（Q3：A 方案）

- DSH 为正式唯一模型入口。
- 禁止自动静默回退旧 API。
- 保留人工启用旧 API 的配置开关。
- 面板明确展示当前模型后端。
- 每次人工回退记录操作者、时间、原因、调用来源。
- 回退期间禁止同一任务被两个模型入口重复执行。
- DSH 故障时自主活动进入暂停状态；恢复后按执行记录决定是否继续。

## 4. 存储与删除治理（D8）

### 4.1 目标

长期保留记忆与历史，同时提供存储查看、归档、清理、恢复、永久删除能力。
**不要求所有数据永久保存，但禁止未经授权自动删除重要记忆。**

### 4.2 存储分级

| 等级 | 内容 | 删除策略 |
|---|---|---|
| L1 核心记忆 | 人格、稳定经验、重要关系 | 默认保护，永久删除需明确确认 |
| L2 重要经历 | 重要日记、重要活动、重要事件 | 长期保留，允许选择性删除 |
| L3 普通历史 | 普通日记、已处理事件、活动历史 | 允许批量归档、导出、删除 |
| L4 临时数据 | 缓存、临时图片、可重建索引 | 允许自动清理 |

等级只控制删除权限，不代表内容价值的客观评判。

### 4.3 面板存储管理

总占用、分类占用、归档占用、回收站占用、最近增长趋势；支持按类型、时间、等级、大小筛选查看。

### 4.4 删除管理

- 自动清理临时文件与可重建缓存。
- 普通历史批量清理。
- 已处理事件按范围清理。
- 日记与经验选择性清理。
- 图片与画廊清理。
- **未处理事件不得通过普通批量清理删除。**
- 删除前展示影响范围与预计释放空间。

### 4.5 回收站

- 普通删除默认先移入回收站，默认保留 30 天，支持恢复。
- 到期后由机主确认永久删除。
- 回收站容量限制与空间预警。
- L1 永久删除需要额外确认。
- 回收站不参与正常记忆检索。

### 4.6 关联保护

- 检查日记、事件、图片之间的引用关系。
- 删除图片时提示仍存在的引用；删除经验时检查其他记忆引用；删除事件时检查当前状态与计划影响。
- 删除必须保持 Memory Hub 索引一致；不允许删除唯一原始记录后留下虚假的有效索引。

### 4.7 空间保护

初始预警：500 MB 提醒、1 GB 黄色、2 GB 建议检查、5 GB 高级预警；支持自定义阈值。
同时监控小鲸鱼数据目录占用与磁盘剩余空间。

### 4.8 审计与安全

- 记录删除对象、时间、来源、释放空间；审计日志不保存被删除正文。
- 永久删除前支持导出；关键文件删除需要确认。
- 不允许自动删除未处理事件、唯一原始记录或核心人设。
- 删除完成后更新 Memory Hub 索引与存储统计。

### 4.9 工程约束

- 面板删除走 **Memory Hub 管理接口**（受审计、分级、回收站），不直接删文件。
- 回收站 = 移动到回收站目录 + 索引标记失效；恢复 = 移回 + 索引重建。
- "唯一原始记录"指未复制到别处的源文件；归档副本不算替代。
- 存储治理依赖 Memory Hub 索引，排在阶段 2.5 之后、阶段 3 之前。

## 5. 实施约束（D9~D10）

### D9 · 修复优先级与"原子写 ≠ 并发安全"

**优先级**

| 优先级 | 问题 | 修复 |
|---|---|---|
| P0 | `autonomous.json` 并发写 | 原子写 + 单写者锁 |
| P0 | 日记三处写入口 | 统一 Diary Writer + 幂等 ID |
| P0 | Token 双账本 | 统一账本，避免覆盖 |
| P1 | `sessions.js` 非原子写 | 临时文件 + rename |
| P1 | 面板记忆类写入 | 全部迁移至 Memory Hub |

**并发安全必须同时满足四条**：

1. 单写者约束；
2. 原子提交（tmp + rename）；
3. 失败重试或明确报错；
4. 崩溃恢复（启动时清理残留、校验半截文件）。

只做原子写不够：两个进程各自读旧值、改、原子替换，仍会丢一次更新。

### D10 · 阶段 1 的四个验收点

| 验收点 | 内容 | 验收标准 |
|---|---|---|
| 1.1 聊天事件发布 | 对话消息、回复、工具执行结果形成统一事件 | 事件不重复、不丢失 |
| 1.2 Token 账本归一 | 所有模型调用走统一费用统计 | 并发调用后账本准确 |
| 1.3 事件可靠性 | 事件 ID、幂等消费、失败重试、恢复 | 模拟进程中断后能恢复未处理事件 |
| 1.4 旧系统兼容 | 旧 QQ 聊天、自主活动、日记继续可用 | 新事件系统故障时不破坏旧系统数据 |

### D10 补充 · 真实 Prompt 延迟基线（新增检查）

短 prompt 的 6 秒不能代表生产。进入阶段 3 前必须用真实输入测量：

| 场景 | 记录 |
|---|---|
| 普通聊天（人设+经验+最近对话） | 首 token、总耗时 |
| 自主意图（人设+日记+状态） | 首 token、总耗时 |
| 自主决策（候选+详情+意图） | 首 token、总耗时 |
| 多 Session 并发 | P50、P95、失败率 |

### 贯穿 4.0 的原则

**不要为了让两个她变成一个她，而牺牲原有 QQ 聊天、自主活动和记忆数据的可靠性。**
4.0 是在原有能力上增加连续性，不是推倒重建。
