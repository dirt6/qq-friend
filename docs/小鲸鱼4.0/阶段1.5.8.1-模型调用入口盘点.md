## 二、逐入口细节

### 入口 1：DSH gateway

```js
// orchestrator.js:63-67
import {
  ask as askDsh, hasSession as dshHasSession,
  getInjectedAt as dshInjectedAt, setInjectedAt as dshSetInjectedAt,
  clockLine as dshClockLine
} from './dsh-gateway.js';
```

**调用链**：

```
orchestrator（一轮对话）
  → dshApplies(chatKey) 判别（config.dsh.enabled + chatKeys 白名单）
  → askDsh(sessionKey, text, {...})
    → withQueue(key)（同一 chatKey 串行）
    → runOnce() → spawn `dsh --profile headless --patch … --json`
```

**失败模式**（现有代码里都能看到）：

| 失败 | 现在怎么处理 | 有记录吗 |
|---|---|---|
| spawn 失败（找不到 dsh） | 返回 null → 回落 API | `dsh-gateway.log` 有一行 |
| 超时（默认 180s） | 返回 null → 回落 | 同上 |
| 非零退出 | 返回 null → 回落 | 同上 |
| 空回复 | 返回 null → 回落 | 同上 |
| 临时目录建不了 | **记 warn**（不回落） | 日志 |
| Session 冲突 | `withQueue` 串行，不冲突 | — |

**已经在记的**：

```js
recordTurn({ chat, backend: 'dsh', cold, session, persona: hash, … })
```

`recordTurn` 记的是**提示词指纹**（人设 hash、经验 id、表情包 hash），**不是调用结果**。

**结论**：DSH 入口有「失败回落到 API」的行为，但**没有一个统一的地方记录"这轮最终走的哪条路"**。

### 入口 3：自主活动

```js
// plugins/autonomous/index.js:702 / 1071
const res = await llm.chatCompletion({ ... });
```

**它和入口 2 是同一个函数**，但**调用语义不同**：
- 入口 2 是"聊天"，失败可以重试、可以回落到静默
- 入口 3 是"她自己想做什么"，失败就是**这一轮白跑**

**现在记录**：

```js
await noteUsage(res);   // → data/token-usage.json（1.2 的账本）
```

**缺的**：失败时**只记一句 warn**，`autonomous.json` 的 `history` 里会有 `error` 字段，但**没有"失败在哪一步"的结构**（意图 / 决策 / 工具 / 发送）。

## 三、现在到底缺什么

### 缺 1：没有统一的调用记录

现在四类信息散在四个地方：

| 信息 | 在哪 |
|---|---|
| 提示词指纹 | `prompt-version.js` 的 `recordTurn` |
| token/成本 | `usage`（session）+ `token-usage.json`（自主） |
| 失败 | `console.warn` + `dsh-gateway.log` |
| 走了哪条路 | **没有**（DSH 回落是隐式的） |

**所以现在回答不了**：

```
这一轮到底走的 DSH 还是 API？
如果是回落，为什么回落？
失败是在模型调用、工具执行还是消息发送？
```

### 缺 2：`fallback` 完全不可见

```js
// orchestrator.js:73
// DSH 任何失败都返回 null，调用方随即落回原来的 API 路径。
```

**这是好事**（不影响聊天），**但没有任何地方记下来**。表现就是：
- 面板看一切正常
- 实际上 DSH 可能一直在失败、一直在回落

**这正是 1.5.8 要解决的。**

### 缺 3：模型成功 ≠ 行动成功

你提的那条很关键：

```
自主活动一轮
  ├─ DSH 调用成功          ← 记了
  ├─ 模型决定画画          ← activit 里有
  ├─ 画图工具执行失败       ← 只有日志
  └─ 最终没有作品          ← 面板可能显示"活跃"
```

**三个层次要分开记**：

| 层 | 内容 | 现状 |
|---|---|---|
| **调用层** | 哪个入口、成功否、耗时、失败码 | ❌ 缺 |
| **决策层** | 模型想做什么（action / intent） | ✅ `autonomous.json` 的 history 有 |
| **执行层** | 工具成没成、消息发没发 | ⚠️ 只有部分（`actions[].result`） |

## 四、建议的统一记录结构（1.5.8.2 的输入）

**不记 Prompt、不记聊天正文**，只记"谁、什么时候、走了哪条路、成没成、多久、为什么失败"。

```json
{
  "id": "call-<8位>",
  "roundId": "round-<8位>",
  "at": "2026-11-01T03:30:00.000Z",
  "purpose": "chat.reply | autonomous.intent | autonomous.decide | memory.consolidate | test.api",
  "backend": "dsh | api",
  "sessionKey": "private:1846383180",
  "dshSessionId": "session-…",
  "status": "success | failed | fallback",
  "durationMs": 6200,
  "fallback": false,
  "failureCode": null,
  "failureDetail": null,
  "model": "deepseek-flash",
  "tokens": { "prompt": 17200, "completion": 166, "cached": 6144 }
}
```

失败例子：

```json
{
  "status": "fallback",
  "backend": "dsh",
  "fallback": true,
  "failureCode": "DSH_TIMEOUT",
  "failureDetail": "180000ms 超时，已回落 API"
}
```

### `failureCode` 的取值建议

| 码 | 含义 |
|---|---|
| `DSH_SPAWN_FAILED` | 起不来（找不到 dsh / 临时目录建不了） |
| `DSH_TIMEOUT` | 超时 |
| `DSH_NONZERO_EXIT` | 非零退出 |
| `DSH_EMPTY_REPLY` | 空回复 |
| `API_HTTP_4XX` | 除 429 的 HTTP 错误 |
| `API_429` | 限频 |
| `API_TIMEOUT` | 超时 |
| `API_EMPTY` | 空回复 |
| `API_BAD_TOOLCALL` | 工具调用格式错 |
| `ABORTED` | 用户中止 |

### 五条原则（按你的要求）

1. **记录真实执行结果** —— 在 gateway / llm 的返回处记，不让模型自己报告
2. **不记完整 Prompt 和聊天正文** —— 只记 hash、长度、token 数
3. **每次调用有独立 ID** —— `call-xxx` 关联 `roundId`
4. **备用入口必须标记** —— `fallback: true` + `failureCode`，不静默
5. **日志有容量上限** —— 参照 1.3 事件归档的 512 KB / 500 MB 体系
