### 2.1 给模型的内容

```json
{
  "rounds": [
    {
      "roundId": "round-42574042",

      "intent": { "intent": "continue", "goal": "看看老大回没回话", "why": "上次留的事" },

        { "action": "share", "objective": "把这篇丢给老大", "result": "success" },
        { "action": "chat", "objective": "把白嫖资源告诉老大", "result": "success" }
      ],
      "stopReason": "完成：没有别的想做的了"
    }
  ]
```

### 2.2 窗口与限制

| 项 | 值 |
|---|---|
| 取最近几轮 | **5**（`recentDigests(5)`） |
| `MAX_DIGESTS` | 50（B5a 已有） |
| 每轮 actions | 最多 12（B5a 已有） |
| 单条 objective | ≤ 120 字（B5a 已有） |

### 2.3 安全跳过（不调模型）

| 条件 | 理由 |
|---|---|
| digest 总数 < 2 | 跨轮证据不可能成立 |
| digest 缺失/损坏 | `readDigests` 已经容错返回 `[]` |

| 本轮 `rec.error` 非空 | 已经在 B5a 的 `buildDigest` 跳过，这里再兜一层 |

**注意**：**`< 2` 就跳过** —— 省一次模型调用（这是"是否需要足够跨轮历史才调用"的答案）。

## 四、程序校验规则

### 4.1 八项校验（机主定的）

| # | 规则 | 实现 |
|---|---|---|
| 1 | `roundIds` 全部来自本次提供的 digest | `digestRoundIds.has(id)` |
| 2 | **至少两个不同 Round** | `new Set(roundIds).size >= 2` |
| 3 | 所有引用 Round 存在于**真实 autonomous history** | 读 `autonomous.json` 的 `history[].roundId` |
| 4 | 不把同一 Round 的多个 Action 当跨轮证据 | **由第 2 条保证**（Action 不参与 roundId 集合） |
| 5 | `text` 不是 action objective 的简单复述/拼接/改写 | 见 4.2 |
| 6 | 四项条件（持续性/方向性/价值性/有依据） | 见 4.3 |
| 7 | `evidenceSummary` 与真实历史相符 | 见 4.4 |
| 8 | 格式错误/字段缺失/证据不足 → 拒绝 | 结构校验 |

### 4.2 第 5 条：怎么判断"复述"

**能做的**（程序）：

```js
function looksLikeObjective(text, objectives) {
  const t = normalize(text);
  for (const o of objectives) {
    const n = normalize(o);
    if (!n) continue;
    // ① 完全相同
    if (t === n) return true;
    // ② 一个是另一个的子串（且长度接近）
    if (t.includes(n) || n.includes(t)) {
      const ratio = Math.min(t.length, n.length) / Math.max(t.length, n.length);
      if (ratio >= 0.7) return true;
    }
  }
  // ③ 两个 objective 的简单拼接
  for (let i = 0; i < objectives.length; i += 1) {
    for (let j = i + 1; j < objectives.length; j += 1) {
      const joined = normalize(objectives[i]) + normalize(objectives[j]);
      if (t === joined) return true;
    }
  }
  return false;
}
```

**做不到的**：**语义改写**（比如"把资源发给老大" → "持续维护和老大之间的信息分享"）。

**结论**：**第 5 条只能挡住明显的复述**，语义改写挡不住。**这一点必须写进风险清单。**

### 4.3 第 6 条：四项条件怎么验

| 条件 | 谁判 | 怎么验 |
|---|---|---|
| **持续性** | 程序 | `roundIds` 去重 ≥ 2 且都真实存在 |
| **方向性** | 模型 | prompt 说清"不要复述 XX 轮做了什么" |
| **价值性** | 模型 | prompt 问"值不值得未来长期关注" |
| **有依据** | 程序 | `evidenceSummary` 每项都有 `support` 非空 |

**方向性和价值性只能靠模型**——程序验不了。**这是设计上的承认。**

### 4.4 第 7 条：`evidenceSummary` 与真实历史相符

**能做的**：

```js
for (const e of evidenceSummary) {
  // ① roundId 必须在 roundIds 里
  if (!roundIds.includes(e.roundId)) return reject('summary 引用了不在 roundIds 里的轮次');
  // ② support 非空
  if (!e.support.trim()) return reject('summary 的 support 为空');
}
```

**做不到的**：**验证 `support` 的内容是否真的对应该 Round**。

**能做的最强校验**：`support` 里至少要出现一次该 Round 的 `objective` 关键词？

**但**：那会假阳性/假阴性。

**结论**：**只能做形式校验**。写进风险清单。

### 4.5 校验失败的错误码

```js
{
  BAD_FORMAT         // 不是 JSON / 缺字段
  NO_CANDIDATE       // candidate: false（**不是错误**，正常跳过）
  ROUND_ID_FOREIGN   // roundIds 里有本次没给过的
  ROUND_ID_MISSING   // roundIds 里有真实 history 里没有的
  TOO_FEW_ROUNDS     // 去重后 < 2
  TEXT_IS_OBJECTIVE  // text 是 objective 的复述
  SUMMARY_MISMATCH   // evidenceSummary 结构不对
}
```

## 六、频率、幂等与重试

### 6.1 每轮最多判断一次

**实现**：`finish` 里调一次，`finish` 只调一次 → **天然满足**。

### 6.2 幂等标识

**`roundId`**。

**判断记录存哪**：

```js
// st.goalJudgeLog（**不进 history**，机主要求"不要把模型调用结果与 Round 原始记录混为一体"）
[
  { roundId: 'round-x', at: ISO, outcome: 'created' | 'no-candidate' | 'rejected' | 'failed' | 'skipped', code: '', goalId: '' }
]
```

**容量**：只留最近 50 条。

**幂等检查**：

```js
if (st.goalJudgeLog.some((x) => x.roundId === rec.roundId)) return;   // 已经判断过
```

### 6.3 重试策略

| 结果 | 重试？ | 理由 |
|---|---|---|
| `created` | ❌ | 已经建了 |
| `no-candidate` | ❌ | 模型判断没有，重试是浪费 |
| `rejected`（校验失败） | ❌ | 同样的输入会得到同样的结果 |
| `failed`（模型调用失败） | ❌ | **下一轮再说**（不重试，避免雪崩） |
| `skipped`（条件不满足） | ❌ | 条件没变 |

**结论**：**一律不重试**。每轮只判断一次，失败就等下一轮。

**避免重复创建**：
- `goalJudgeLog` 的 `roundId` 幂等
- `createAutonomousGoal` 的 `createGoalCore` 还有同文本去重

**双保险**。

## 七、模型调用失败处理

| 失败类型 | 处理 |
|---|---|
| 网络/超时/HTTP 错误 | `warn` + 记 `failed`，**不抛** |
| 返回空/非法 JSON | 记 `failed`，`warn` |
| 返回 `candidate: false` | 记 `no-candidate`，**不 warn**（这是正常结果） |
| 校验失败 | 记 `rejected`，`warn`（带 code） |

**统一包在 `try/catch` 里**，任何异常都只 `warn`。

## 八、成本与预算

### 8.1 每次调用的 token 估算

| 部分 | 估算 |
|---|---|
| system prompt（判断说明） | ~250 tokens |
| 输入（5 条 digest，每条 ~200 字） | ~1500 tokens |
| 输出（JSON） | ~150 tokens |
| **合计** | **~1900 tokens / 轮** |

### 8.2 对比

- **Planner 一次决策**：900~1500 tokens
- **本轮判断**：~1900 tokens（**相当于多一次规划**）

### 8.3 优化

**只对"有足够跨轮历史"的情况调用**：

```js
if (digests.length < 2) return { skipped: 'not-enough-rounds' };   // 省掉一次调用
```

**更进一步**（可选）：**只在最近 2 轮都成功时判断**（排除异常轮次）。

**当前建议**：**只做 `digests.length < 2` 的跳过**，不做更复杂的过滤。

### 8.4 预算保护

**复用现有的 `budgetGate`**？还是独立？

**现状**：`runSession` 有 `maxModelCalls` / `maxInputTokens` 限制。

**B5b 的调用应该在 `finish` 之后** —— **那时预算已经结算完了**。

**风险**：**B5b 的调用不受本轮预算约束** → 可能超支。

**建议**：**B5b 自己检查一次预算**（用 `token-ledger` 的 `readDay`），超了就跳过。

**但**：这会让逻辑复杂。

**折中**：**先不做预算检查**，观察几轮看实际成本。**但要记录 token**（`chatCompletionObserved` 会自动记）。

## 十二、要你确认的四个决定

### ① 判断窗口取几轮

**我建议 5 轮**（`recentDigests(5)`）。

**多了**：token 涨、注意力分散
**少了**：跨轮证据不足

### ② `text` 的复述检测阈值

**我建议**：
- 完全相同 → 拒绝
- 包含关系且长度比 ≥ 0.7 → 拒绝
- 两个 objective 直接拼接 → 拒绝

**这个阈值可能误伤**（比如"持续关注 CSP"和"准备 CSP"长度比 0.6）。

**你接受吗？**

### ③ 每轮都判断，还是攒够 N 轮才判断

**我建议每轮**（`digests.length >= 2` 才调）。

### ④ 预算检查

**我建议先不做**（观察几轮），但**记录 token**。

**同意吗？**
