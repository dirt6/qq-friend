# `messages[].raw` / `toolImages` 只读评估

> 时间：2026-11-01 03:15（Asia/Shanghai）
> 脚本：`node scripts/audit-session-raw.mjs`
> **严格只读**：没改任何 Session、没碰 DSH_HOME、没删文件、没建副本、没动归档规则

---

## 结论先说

**不建议剥离 `raw`。** 两个理由：

1. **它只占 1.28 MB（1.7%）** —— 省下来几乎没有意义
2. **它有真实的功能依赖** —— `app.js:1816` 用 `raw.usage` 做**每次 LLM 调用的精确用量统计**，剥了账本就退化成"只能看聚合值"

**真正的大头不在 raw**，在那 670 个未满 7 天的会话（70 MB，prompt 占 97.6%）。等它们到期归档就行。

## ② 代码依赖

| 目标 | 处数 | 真实依赖 |

### 决定性的一处：`src/app.js:1816`

```js
// 逐次调用展开：每条 message.raw 有独立的 usage / created / model
const raw = m?.raw;
const ru = raw.usage || {};
const rp = Number(ru.prompt_tokens) || 0;
const rc = Number(ru.completion_tokens) || 0;
if (!rp && !rc) continue;
exactRows.push({
  promptTokens: rp,
  completionTokens: rc,
  cachedTokens: Number(ru.prompt_tokens_details?.cached_tokens) || 0,
  at: Number(raw.created) * 1000,     // ← 精确到秒的时间
  model: String(raw.model || s.model || '') || '(未知)'
});
```

**用途**：`buildUsageStats` 里"逐次调用"的 token / 成本 / 时间 / 模型。

**剥掉会怎样**：
- 用量统计从"每次调用一行"退化成"每个会话一个汇总"
- **`cachedTokens` 全部丢失**（顶层 `usage` 有，但分不到单次）
- 按小时/按模型拆分的图表会变粗

**这条依赖是硬的。**

## ③ 功能影响（如果剥离）

| 能力 | 现在 | 剥离后 |
|---|---|---|
| 每次 LLM 调用的 token / 成本 | ✅ 精确 | ⚠️ 只能看会话汇总 |
| 缓存命中率（cachedTokens） | ✅ 每次都有 | ❌ 丢失 |
| 调用时间精确到秒 | ✅ `raw.created` | ⚠️ 只有会话 startedAt |
| 单次调用用的哪个模型 | ✅ `raw.model` | ⚠️ 只有会话级 model |
| 复盘"那次模型到底返回了什么" | ✅ 完整 | ❌ 只剩 content |
| `toolImages`（工具拿了几张图） | ✅ | ⚠️ 但价值本来就低 |

## A. 轨迹 vs 内容的区分（你要求的第一项）

`raw` 里有五类信息，价值完全不同：

| 类别 | 例子 | 值不值得留 |
|---|---|---|
| **模型元数据** | `id` / `model` / `created` / `system_fingerprint` | **留**（用量统计依赖） |
| **用量** | `usage.prompt_tokens` / `cached_tokens` / `reasoning_tokens` | **必须留**（账本依赖） |
| **模型响应** | `choices[0].message.content` / `reasoning_content` | 留（复盘唯一证据） |
| **工具调用** | `choices[0].message.tool_calls` | 留（和顶层重复，但结构完整） |
| **选择元信息** | `choices[0].finish_reason` / `logprobs` | 留（排查"为什么没说话"要用） |

**没有发现"纯垃圾"**。

## B. 重复存储检查（你要求的第二项）

```
检查 1365 条带 raw 的消息：
  raw.choices[0].message.content 与顶层 content 相同：1365 条（100%）
  raw.choices[0].message.tool_calls 与顶层 tool_calls 相同：1345 条（99%）
```

**确实重复**。但 `raw` 还带了顶层没有的：`id` / `model` / `created` / `usage` / `finish_reason` / `system_fingerprint`。

**按你说的"不能仅凭内容相似就认定可以删除"** —— 这里的判断是：

- `content` / `tool_calls` 部分可以视作重复
- 但**元数据部分是独有的，且账本依赖它**
- 拆开剥离（只留元数据不留 content）需要改结构，收益 0.47 MB，**不值得**

这才是"不重复保存"的真正实现路径 —— 不是去抠 raw 的 1.7%，而是让到期归档持续跑。

## 六、建议

**不做 1.5.7.7（raw 剥离）。** 理由：

1. 收益 1.7%，风险是账本精度
2. `raw` 是复盘"她为什么这么回"的唯一证据
3. 你说得对：4.0 后面要统一模型入口，那时候 `raw` 就是排查问题的第一手资料

**该做的是**：
- 让 `archive-sessions.mjs` 定期跑（现在 650 个还没到期）
- 1.5.8 之后回到主线
