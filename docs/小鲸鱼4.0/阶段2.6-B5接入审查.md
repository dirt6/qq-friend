## 二、推荐的 Round 结束接入点及理由

### 2.1 结论：**`finish` 里 `writeState` 之后**

```js
pushHistory(st, rec);
try { writeState(STORE, st); } catch (e) { warn(...); }
// ↓ 这里
try { summarizeRound(rec); } catch (e) { warn(...); }
try { appendActivityLog(rec); } catch (e) { warn(...); }
```

### 2.2 为什么是这个位置

| 要求 | 是否满足 |
|---|---|
| 所有 Action 记录完成后 | ✅ 主循环已结束 |
| 不会在每个 Action 后触发 | ✅ `finish` 只在活动结束时调 |
| 不会因异常退出而重复触发 | ✅ `finish` 只调一次（`return` 语义） |
| 同一 Round 内不会多次调用 | ✅ |
| Round 已完整落盘 | ✅ `writeState` 在前，读 `autonomous.json` 能拿到本轮 |
| 汇总失败不影响 Round 结束 | ✅ 包在 `try/catch` 里，只 `warn` |
| 不需要重构生命周期 | ✅ 只加一行调用 |

### 2.3 并发 Round

**现状**：`running` 标志位保证**同一时刻只有一轮**（`if (running) return;`）。

**所以**：**不会有并发 Round** ✅

**但**：多个**进程**可能同时跑（`autonomous-run.mjs` + 机器人）→ `writeState` 有文件锁保护。

**汇总读的是 `autonomous.json`**（已落盘）→ **读到的是最新的** ✅

## 三、可信 evidence 的构造和验证流程

### 3.1 B3 的实现（已审）

```js
export function createAutonomousGoal({ text, evidence, knownRounds = null }) {
  const v = validateGoalEvidence(evidence, { knownRounds });   // ← 校验
  if (!v.ok) return { ok: false, code: v.code };
  const r = createGoalCore({ text, source: 'autonomous' });    // ← 内部实现
  ...
}
```

**`validateGoalEvidence` 检查**：

| 检查 | 实现 |
|---|---|
| evidence 是对象 | `!evidence \|\| typeof !== 'object'` |
| type 合法 | `EVIDENCE_TYPE.includes(evidence.type)` |
| 有 roundIds | `Array.isArray && length > 0` |
| **去重后 ≥ 2** | `[...new Set(...)]` |
| **Round 真实存在** | `knownRoundIds()` 读 `DATA_DIR/autonomous.json` 的 `history[].roundId` |
| 有 reason | `String(evidence.reason).trim()` |

### 3.2 模型能否伪造

**关键问题**：`knownRounds` 参数。

```js
function knownRoundIds() {
  const f = path.join(DATA_DIR, 'autonomous.json');
  const j = JSON.parse(fs.readFileSync(f, 'utf8'));
  for (const r of j.history || []) if (r.roundId) out.add(String(r.roundId));
}
```

**默认走 `knownRoundIds()`**（真实 history）✅

**但**：`knownRounds` 参数**可以被调用方注入**（测试用）。

**风险**：如果 B5 传了 `knownRounds`，就等于自己给自己发证据。

**B5 的约束**：**绝对不能传 `knownRounds`**，必须让 `createAutonomousGoal` 自己读真实 history。

### 3.3 模型提供的 Round ID 会怎样

**场景**：模型说"我这两轮在关注 X，roundId 是 r-abc 和 r-def"。

**如果 `r-abc` / `r-def` 不在真实 history 里** → `EVIDENCE_ROUND_NOT_FOUND` ✅

**如果它们在，"但内容不对"** → **B3 校验不了**（它只查 ID 存在）⚠

**这是 B5 必须补的第一道**：**模型提的 roundIds 不能直接信**，要由**程序从真实 history 里挑**。

### 3.4 推荐流程

```
① 程序从 autonomous.json 取最近 N 轮（比如 5 轮）
   → 只取 roundId + intent + actions[].goal + actions[].next（很小）
② 交给模型判断："这些轮次里有没有反复出现的长期方向？"
   → 模型输出 { candidate: bool, text, roundIds: [...], reason }
③ 程序校验：
   · roundIds 必须是 ① 里给过的那几个（**不能是模型自己编的**）
   · 至少 2 个**不同**的 Round
   · text 不是 Action Objective 的复述
④ 调 createAutonomousGoal({ text, evidence: { type, roundIds, reason } })
   ← **不传 knownRounds**
```

**关键**：**模型只能从"程序给过的 Round"里选**，不能自己编 ID。

## 四、候选方向判断方案

### 4.1 四条条件怎么落地

| 条件 | 谁判断 | 怎么做 |
|---|---|---|
| **持续性**（跨 Round） | **程序** | `roundIds` 去重后 ≥ 2 |
| **方向性**（不是一次性动作） | **模型** | prompt 里说清"不要复述这一轮做了什么" |
| **价值性** | **模型** | prompt 里问"值不值得未来长期关注" |
| **有依据** | **程序** | `reason` 非空 + roundIds 真实 |

### 4.2 不使用机械门槛

**不写**：`if (sameTopicTimes >= 3) createGoal()`

**改成**：模型判断 + 程序校验。

### 4.3 字段的边界（机主强调）

| 字段 | 是什么 | **能不能**变成 Goal |
|---|---|---|
| `decision.goal` | Action Objective | ❌ **不能** |
| `decision.next` | 下一步可能做什么 | ❌ **不能** |
| Pending | 具体未完成事项 | ❌ **不能** |
| **Autonomous Goal** | 跨 Round 持续关注的方向 | ✅ 只能由上面的流程产生 |

## 五、重复触发、并发、异常退出的处理方案

### 5.1 重复触发

**现状**：`finish` 只调一次（`return` 语义）。

**但**：如果 `summarizeRound` 里又调了 `finish`？→ **不会**（它是独立函数）。

**防护**：`rec.summarized` 标记（幂等）。

### 5.2 并发

**同一进程**：`running` 标志位保证串行。

**多进程**：`writeState` 有文件锁；`createAutonomousGoal` 的 `createGoalCore` 有锁。

**但**：汇总阶段读 `autonomous.json` → **读到的是最新的** ✅

### 5.3 异常退出

**`finish` 在 `catch` 里也被调用**（1696）→ 异常轮次也会汇总。

**要不要汇总异常轮次？**

**建议**：`rec.error` 非空时**跳过汇总**（那轮没有可信的 Action 记录）。

### 5.4 汇总失败

**包在 `try/catch` 里，只 `warn`** —— 不影响 `appendActivityLog` 和写日记。

## 八、风险清单及尚未验证的假设

### 8.1 风险

| # | 风险 | 严重度 | 缓解 |
|---|---|---|---|
| **R1** | 模型编造 roundId | 高 | **程序只认自己给过的 Round**（不传 knownRounds） |
| **R2** | 每轮都调一次候选判断 → 成本翻倍 | 中 | 可以只在"有 2+ 轮历史"时才判断 |
| **R3** | prompt 预算紧，放不下判断说明 | 中 | **独立调用**（不复用 planner 的 prompt） |
| **R4** | 跨轮 ≠ 充分条件（两个 Round 出现同一关键词就建 Goal） | **高** | 机主明确要求；靠 prompt 说清 + 程序校验 `text` 不是复述 |

| **R6** | 异常轮次被汇总 | 低 | `rec.error` 非空时跳过 |
| **R7** | 多进程并发汇总 | 低 | `writeState` 有锁；汇总只读 |
