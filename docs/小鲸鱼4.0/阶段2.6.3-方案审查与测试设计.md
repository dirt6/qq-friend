## 一、`NO_PROPOSAL` 与 `CONFIRMATION_REQUIRED` 的区分

| 错误码 | 什么时候返回 | 谁能触发 |
|---|---|---|
| **`NO_PROPOSAL`** | `answerConfirmation()` 时**没有待处理的 proposal** | 只有"回答"接口 |
| **`CONFIRMATION_REQUIRED`** | `completeGoal` / `cancelGoal` / `supersedeGoal` 时，`user_directed` **没有 proposal** | 只有三个"执行"接口 |

**关键约束**（机主明确）：

> 普通 autonomous Goal 的合法终态操作不能被 `NO_PROPOSAL` 错误阻断。

**实现**：

```js
function endGoal(id, kind, { by, reason }) {
  // autonomous → 直接过，**完全不看 proposal**
  // user_directed → 才检查 proposal
}
```

**测试要验**：`autonomous` 的 `completeGoal` 在**没有任何 proposal** 的情况下成功，且返回值里**没有** `NO_PROPOSAL`。

## 二、`endGoal` 不导出

**对外导出**：

```
completeGoal / cancelGoal / supersedeGoal
```

**内部**：

```
endGoal(id, kind, { by, reason })   ← 不导出
canEndGoal(g, kind)                 ← 可选导出（测试用），先不导出
```

**三个接口各自做的事**：

```js
export function completeGoal(id, { by = 'unknown', reason = '' } = {}) {
  return endGoal(id, 'complete', { by, reason });
}
```

**检查全部在 `endGoal` 里**：

1. goal 存在？
2. 状态允许转换？（`canTransition(status, 'completed')`）
3. 权限？（`autonomous` 直接过；`user_directed` 要有 `answer === 'yes'` 的匹配 proposal）
4. proposal 过期了？

**外部无法绕过**：`endGoal` 不导出，只能通过三个接口进去。

## 三、`expireProposals` 的规则

### 3.1 不在读时清理

```js
readCompanion()  // 只读，不写盘，不清理
```

**理由**：读操作频繁（聊天、面板、每次注入），不能因为读就写盘。

### 3.2 在写入接口的锁内惰性清理

**四个接口**（`proposeCompletion` / `markConfirmationAsked` / `answerConfirmation` / `endGoal`）在 `updateCompanion(fn)` 的 `fn` 里：

```js
const r = updateCompanion((st) => {
  // ① 统一的 now（这一批操作用同一个时间快照）
  const now = Date.now();
  const expired = expireProposalsIn(st, now);   // 清掉过期的，返回 id 列表
  // ② 再做本接口的事
  ...
});
```

### 3.3 统一时间快照

**为什么**：如果一个操作里要判断多个 goal 的过期，用**同一个 `now`**，避免"判断到一半时间变了"。

**实现**：

```js
function expireProposalsIn(st, now) {
  const out = [];
  for (const g of st.goals || []) {
    if (!g.proposal) continue;
    const exp = Date.parse(g.proposal.expiresAt || '');
    if (Number.isFinite(exp) && exp < now) {
      g.proposal = null;      // **只清 proposal，不动 status**
      out.push(g.id);
    }
  }
  return out;
}
```

### 3.4 过期只清 proposal

**状态不变** —— 过期不是取消、不是完成、不是拒绝。

**测试要验**：proposal 过期后，`goal.status` 还是原值。

### 3.5 新 proposal 不继承旧字段

**`proposeCompletion` 覆盖时，整块替换**：

```js
g.proposal = {
  kind,
  proposedAt: now,
  proposedBy: 'autonomous',
  reason: String(reason || '').slice(0, 200),
  askedAt: null,        // ← 重置
  askedRound: null,     // ← 重置
  expiresAt: null,      // ← 重置
  answerAt: null,       // ← 重置
  answer: '',           // ← 重置
  answerQuote: ''       // ← 重置
};
```

**不能**：`Object.assign(g.proposal, {...})`（会保留旧字段）。

**测试要验**：覆盖后 `askedAt` / `answer` / `answerQuote` 都是空。

## 四、`clearGoal` 的日志策略

### 4.1 返回值

```js
clearGoal({ source })
// → { ok: true, goal } | { ok: false, error, code } | { ok: true, skipped: 'no-active-goal' }
```

### 4.2 调用点（`plugins/autonomous/index.js`）

```js
const cg = readCompanion().goal;
if (cg && settledTexts.includes(cg.text)) {
  const r = clearGoal({ source: 'autonomous' });
  if (!r.ok) logClearGoalFailure(cg.id, r.code, 'complete', 'autonomous');
}
```

### 4.3 去重（同一 Goal + 同一错误原因连续失败）

**模块级 Map**：

```js
const lastClearFail = new Map();   // key: `${goalId}:${code}` → true

function logClearGoalFailure(goalId, code, operation, source) {
  const key = `${goalId}:${code}`;
  if (lastClearFail.get(key)) return;   // 连续同一个，不重复记
  lastClearFail.set(key, true);

  // 权限拒绝用 warn，意外异常用 error
  const isPerm = ['CONFIRMATION_REQUIRED', 'NOT_ASKED', 'NOT_CONFIRMED',
                  'PROPOSAL_EXPIRED', 'KIND_MISMATCH', 'TERMINAL_STATE',
                  'INVALID_TRANSITION'].includes(code);
  const msg = `Goal 没完成 goalId=${goalId} code=${code} op=${operation} source=${source}`;
  if (isPerm) warn(msg); else error(msg);
}
```

**成功后重置**：

```js
// clearGoal 成功时
lastClearFail.clear();   // 或者只清这个 goal 的
```

**判断**：模块级 `Map` + 一个函数，**不超过 20 行**，不算"明显扩大范围" ✅

**日志内容**（机主要求）：

```
goalId / errorCode / operation / source
```

**不记**：完整 Goal 文本、用户原话。

## 六、错误码最终表

| code | 含义 | 谁返回 |
|---|---|---|
| `NOT_FOUND` | 没有这条 Goal | 全部 |
| `TERMINAL_STATE` | 已经是终态 | propose / end |
| `INVALID_KIND` | kind 不合法 | propose |
| `INVALID_TRANSITION` | 状态转换不允许 | end |
| `ALREADY_DONE` | 已经是目标状态（幂等） | end |
| `CONFIRMATION_REQUIRED` | user_directed 没有 proposal | end |
| `KIND_MISMATCH` | proposal kind 和操作不一致 | end |
| `NOT_ASKED` | 有 proposal 但没问过 | end / answer |
| `NOT_CONFIRMED` | 问了但答案不是 yes | end |
| `PROPOSAL_EXPIRED` | proposal 过期 | end / answer |
| **`NO_PROPOSAL`** | **回答时没有待处理 proposal** | **answerConfirmation** |

**11 个。**

**`NO_PROPOSAL` 和 `CONFIRMATION_REQUIRED` 的差别**：

- `NO_PROPOSAL`：**你正在回答一个不存在的东西**
- `CONFIRMATION_REQUIRED`：**你想结束一个还没被确认的东西**
