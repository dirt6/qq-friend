## 十、B8 的设计方向（Memory Hub 的基础）

### 10.1 核心判断：**不要新建第六层**

**现有五层各自有职责**（经验 / 聊天 / 日记 / 轨迹 / 状态），**不该合并**。

**Memory Hub 应该是"统一视图 + 统一操作"，不是"统一存储"**。

### 10.2 三层能力设计

#### 能力 A：**来源（provenance）**

**每条记忆都该能回答"你从哪知道的"**。

**最小可行**：

```js
{
  origin: {
    kind: 'chat' | 'autonomous' | 'diary' | 'user_stated' | 'inferred',
    ref: 'chatKey 或 roundId 或日期',
    at: ISO,
    quote: '原话片段（如果有）'
  }
}
```

**对 learned.json**：加 `origin` 字段（不改现有字段）。

**对日记**：**日记是"她写的"，来源是"当时的活动"** → 需要关联 `roundId`。

#### 能力 B：**置信级别（confidence）**

**区分事实 / 推测**：

```js
{
  kind: 'fact' | 'inference' | 'preference' | 'correction',
  confidence: 0~1   // 可选
}
```

**关键**：**不是所有记忆都要标注** —— 只有**可能被误解为事实的推测**才需要。

**对 learned.json**：加 `kind` 字段。

**对聊天记忆的 `impressions`**：**天然是推测** → 明确标注。

#### 能力 C：**统一入口（可控性）**

**不合并存储，但提供统一操作**：

```js
// 一个只读的"记忆索引"
memoryHub.list({ kind, since, query })
memoryHub.get(id)
memoryHub.update(id, patch)     // 只能改可控字段
memoryHub.remove(id)
memoryHub.trace(id)             // 追溯来源链
```

**关键**：**Hub 是门面，不是新存储**。每个操作转发到对应的层。

### 10.3 优先级（用户说"应该是基础，不是最后补"）

| 能力 | 成本 | 价值 | 优先级 |
|---|---|---|---|
| **A. 来源** | 中（改 3 个层的写入） | **高**（否则无法判断可信度） | **P0** |
| **B. 置信级别** | 低（加字段） | **高**（区分事实/推测） | **P0** |
| **C. 统一入口** | 高（新模块 + 面板） | 中（没有也能用） | **P1** |

**我建议**：**A + B 先做**（加字段，不改存储），**C 后做**（门面可以慢慢来）。
