## 一、两套 Session 必须分开看

审计跑出来的关键事实：

| | QQ-agent | DSH |
|---|---|---|
| 位置 | `data/sessions/<id>.json` | `data/dsh-home/sessions/--E-dsh-QQ-agent--/session-<uuid>/session.v4.jsonl.zstd` |
| 数量 | 1304 个 | 1 个活跃 + 10 个旧的 |
| 每个 | 平均 3.4 条消息 / 107 KB | 最大的 15.5 MB（压缩后） |
| 是什么 | **每轮的记录** | **真正的长上下文** |
| 谁在用 | 面板、重试、等待恢复 | `--session-id` 的上下文 |

**映射关系**（`data/dsh-sessions.json`）：

```json
"private:1846383180": {
  "sessionId": "session-2de90a0a-2759-467c-bc89-2eadd9161a48",  ← 那个 15.5 MB 文件
  "turns": 723,        ← 机主记的 717，实际 723
  "createdAt": "2026-10-24T10:17:28Z",
  "lastUsedAt": "2026-11-01T00:09:06Z"
}
```

### 结论：两套是解耦的

- DSH 只认 `dsh-sessions.json` 里的 `sessionId`，**从不读** `data/sessions/*.json`
- QQ-agent 的 session 文件只给面板/重试/等待恢复用，**不影响 DSH 的上下文**

**所以归档 QQ-agent 的 session 文件，对 DSH 的 723 turns 零影响。** 这条已经过代码验证，不是推测。

## 二、生命周期规则

| 动作 | 条件 | 处理 | 依据 |
|---|---|---|---|
| **创建** | 新一轮聊天或新任务 | 沿用现有（每批消息一个） | 审计确认天然轮换 |
| **恢复** | Session 文件完整且 `status` 允许 | 沿用现有（`retry` 要求 error、等待要求 waiting） | 1.5.5 已加原子写 |
| **归档** | `status === 'done'` **且** `endedAt` 超过 7 天 **且** 没有 `keepForever` | **剥离 4 个冗余字段** | 本方案 |
| **暂缓** | `running` / `waiting` | 不处理 | 进行中 |
| **暂缓** | `error` | 不处理（可能要重试） | `retry()` 会读它 |
| **暂缓** | `aborted` | 先检查有没有未完成任务 | 机主补充 |
| **长期保留** | `keepForever: true` | **永不自动归档** | 本方案 |
| **删除** | 任何情况 | **默认不自动删除**，机主确认后执行 | 机主决策 |

### 重要：归档 ≠ 删除

归档只剥离冗余字段，**聊天记录、用量、时间、触发、模型全部保留**。

## 三、三个保护机制

### 3.1 长期保留标记

```json
{
  "keepForever": true,
  "keepReason": "重要的游戏开发讨论",
  "keepSetAt": "2026-11-01T02:45:00Z"
}
```

**优先级最高**：任何自动流程先看这个字段，是 true 就直接跳过。

### 3.2 归档版本标记

```json
{
  "archive": {
    "version": 1,
    "archivedAt": "2026-11-01T02:45:00Z",
    "promptDigest": {
      "hash": "a1b2c3d4e5f6a7b8",
      "systemChars": 9292,
      "userChars": 4102,
      "inputMessages": 12,
      "capturedAt": "2026-11-01T02:45:00Z"
    },
    "stripped": ["systemPrompt", "userPrompt", "excludedTools", "inputMessages"],
    "bytesBefore": 109568,
    "bytesAfter": 12288
  }
}
```

**作用**：
- `archive.version` 存在 = 已归档过，**跳过**（防重复归档）
- 以后升级归档格式时，按 `version` 区分
- `stripped` 记录**到底剥了什么**，可审计
- `bytesBefore/After` 是"省了多少"的证据

### 3.3 可恢复性检查（归档前后各一次）

归档前：

- [ ] `status === 'done'`
- [ ] `endedAt` 存在且 > 7 天
- [ ] 没有 `archive` 字段（没归档过）
- [ ] 没有 `keepForever`
- [ ] `messages` 是非空数组
- [ ] JSON 能完整解析

归档后：

- [ ] `messages` **逐字节不变**（长度、每条的 text/mid/ts 都对得上）
- [ ] `usage` **完全不变**
- [ ] `status` / `startedAt` / `endedAt` / `trigger` / `model` 不变
- [ ] `promptDigest.hash` 成功生成（非空、16 位十六进制）
- [ ] 新文件 JSON 能解析
- [ ] 文件确实变小了（`bytesAfter < bytesBefore`）
- [ ] **`sessions.get(id)` 拿到它时不会进恢复流程**：
      `retry()` 要求 `status === 'error'`、等待恢复要求 `status === 'waiting'`，
      而归档只处理 `done` → **结构上不可能被恢复**
- [ ] **DSH 不受影响**：`dsh-sessions.json` 里的 `sessionId` 没被碰过（这条只读校验，不改）

## 四、归档执行流程

```
扫描 data/sessions/*.json
   ↓
① 解析 + 基础校验（能解析、有 id）
   ↓
② 状态过滤：status === 'done'
   ↓
③ 时间过滤：endedAt 距今 > 7 天
   ↓
④ 保护过滤：无 keepForever、无 archive.version
   ↓
⑤ 生成 promptDigest（systemPrompt+userPrompt+inputMessages 的 sha1）
   ↓
⑥ 剥离 4 个字段，写入 archive 元数据
   ↓
⑦ 写临时文件 → 重新解析校验 → 原子 rename
   ↓
⑧ 归档后校验（第七节清单）
   ↓
失败 → 保留原文件 + 记日志 + **不报告成功**
```

### 每一步的失败处理

| 步骤失败 | 处理 |
|---|---|
| 解析失败 | 跳过，记 `bad-json` |
| 状态不符 | 跳过（正常） |
| 时间不够 | 跳过（正常） |
| 有保护标记 | 跳过（正常） |
| 生成 digest 失败 | 跳过，记日志 |
| 写 tmp 失败 | 保留原文件，记日志 |
| rename 失败 | 保留原文件 + 清理 tmp，记日志 |
| 归档后校验失败 | **保留原文件**（如果 rename 已发生，则从 tmp 恢复不了 → 必须先校验再 rename） |

**关键顺序**：**先写 tmp + 校验 tmp，再 rename**。校验失败时原文件还没动。

## 六、面板手动提前归档（机主补充）

7 天是默认等待期，但允许手动提前。

**接口设计**（1.5.7.5 之后再做）：

```
POST /api/sessions/archive
{ "id": "mvwliv0t-7710422c" }     // 单个
{ "ids": [...] }                   // 批量
{ "dryRun": true }                 // 先看效果
```

**前置检查**：只允许 `done` 的会话；`keepForever` 的要先取消标记。

**注意**：这个接口属于**记忆类写操作**吗？

**我的判断：属于内容管理，不属于记忆管理。** 理由：
- 它不改变"她记得什么"，只改变"记录存在什么形态"
- 聊天内容一条不少（`messages` 原样保留）
- 所以保留在面板，但要有二次确认 + 显示"会剥离哪些字段"

## 九、要你确认的四件事

1. **7 天**这个默认等待期合适吗？（现在 1304 个会话全部在 30 天内，7 天口径下大约能归档 653 个）
2. **`aborted` 怎么处理**？你说"先检查是否有未完成任务"——具体查什么？
   我的建议：`aborted` **一律不归档**（数量少，只有 4 个，省不了多少还容易出错）。
3. **面板手动归档**归到"内容管理"（保留权限）还是"记忆管理"（收回）？
4. **归档后如果她需要"那时候聊了什么"**——`messages` 还在，但 `systemPrompt` 没了。
   要不要在归档时额外存一份**极简摘要**（比如每轮的第一句话），方便将来检索？这会占一点空间（约 1~2 KB/会话）。
