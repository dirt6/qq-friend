## 二、调用点审查

### 2.1 `clearGoal` 的签名与调用

**签名**：`clearGoal({ source })` —— **没有 id 参数**，内部找 `active` 的。

**生产唯一调用点**（`plugins/autonomous/index.js:245`）：

```js
const cg = readCompanion().goal;                              // 兼容视图 = active
if (cg && settledTexts.includes(cg.text)) clearGoal({ source: 'autonomous' });
```

**返回值被完全忽略。**

### 2.2 改成方案 B 的影响

```js
// 新实现
export function clearGoal({ source = 'unknown' } = {}) {
  const cur = activeGoal();
  if (!cur) return { ok: true, skipped: 'no-active-goal' };
  return completeGoal(cur.id, { by: source, reason: '方向变成完成状态' });
}
```

| 场景 | 现在 | 改后 |
|---|---|---|
| active 是 autonomous | 转 completed | **一样** |
| active 是 user_directed（无确认） | 转 completed（**绕过权限**） | **失败，返回 CONFIRMATION_REQUIRED** |
| 没有 active | 什么都不做 | 返回 `{ ok: true, skipped }` |

**对调用点的影响**：

```js
// 调用点忽略返回值，所以不会崩
if (cg && settledTexts.includes(cg.text)) clearGoal({ source: 'autonomous' });
```

**但用户要求"不能静默失败"** → 调用点要**加日志**：

```js
if (cg && settledTexts.includes(cg.text)) {
  const r = clearGoal({ source: 'autonomous' });
  if (!r.ok) log(`Goal 没完成：${r.error}`);   // 不抛，不影响 Pending 结算
}
```

**关键**：`settlePending` 已经在 `clearGoal` **之前**执行完毕 → **Goal 失败不回滚 Pending** ✅

### 2.3 其他调用点

`setGoal` / `createGoal` / `pauseGoal` / `resumeGoal` 都**不调 `clearGoal`**。

**所以只有 1 处要加日志。**

## 四、接口签名

### 4.1 数据结构

```js
goal.proposal = {
  kind: 'complete' | 'cancel' | 'supersede',
  proposedAt: ISO,
  proposedBy: 'autonomous',
  reason: string,              // ≤ 200 字
  askedAt: ISO | null,         // null = 还没问
  askedRound: string | null,   // roundId（机主要求可追溯）
  expiresAt: ISO | null,       // **askedAt + 7 天**；未询问时为 null
  answerAt: ISO | null,
  answer: 'yes' | 'no' | 'later' | '',
  answerQuote: string          // ≤ 100 字
}
```

**关键**：`expiresAt` **只在 `askedAt` 写入时设置**（未询问不启动倒计时）。

### 4.2 提议

```js
proposeCompletion(id, { kind, reason })
// → { ok, goal, proposal } | { ok: false, error, code }
```

| 情况 | 结果 |
|---|---|
| goal 不存在 | `{ ok: false, error: '没有这条 Goal', code: 'NOT_FOUND' }` |
| 终态 | `{ ok: false, error: '终态不能再提议', code: 'TERMINAL_STATE' }` |
| kind 非法 | `{ ok: false, error: 'kind 不合法', code: 'INVALID_KIND' }` |
| 已有 proposal | **覆盖**（新的替换旧的，`askedAt` 重置为 null） |
| 正常 | 写入 proposal，**不改 status** |

### 4.3 标记已问

```js
markConfirmationAsked(id, { roundId })
// → { ok, shouldAsk: boolean, proposal, error? }
```

| 情况 | `shouldAsk` |
|---|---|
| 没有 proposal | `false` |
| `askedAt` 已有值（**且未过期**） | `false`（不重复问） |
| `askedAt` 有值但**已过期** | `false`（过期清理后没有 proposal） |
| 第一次问 | `true`，写 `askedAt` + `askedRound` + **`expiresAt = askedAt + 7d`** |

### 4.4 回答

```js
answerConfirmation(id, { answer, quote })
// → { ok, goal, applied: boolean, error?, code? }
```

| answer | 处理 |
|---|---|
| `'yes'` | 执行对应操作（`completeGoal` / `cancelGoal` / `supersedeGoal`）→ 转终态 |
| `'no'` | 清掉 proposal，状态不变 |
| `'later'` | 清掉 proposal，状态不变 |
| 没有 proposal | `{ ok: false, code: 'NO_PROPOSAL' }` |
| **proposal 已过期** | `{ ok: false, code: 'PROPOSAL_EXPIRED' }` —— **不执行** |

### 4.5 三个执行接口

```js
completeGoal(id, { by, reason })    // → active/completed
cancelGoal(id, { by, reason })      // → active/paused → cancelled
supersedeGoal(id, { by, reason })   // → active/paused → superseded
```

**内部统一走 `endGoal(id, 'complete'|'cancel'|'supersede', { by, reason })`**。

### 4.6 `endGoal` 的权限检查

```js
function canEndGoal(g, kind) {
  if (g.source === 'autonomous') return { ok: true };
  const p = g.proposal;
  if (!p) return { ok: false, code: 'CONFIRMATION_REQUIRED', error: '...' };
  if (p.kind !== kind) return { ok: false, code: 'KIND_MISMATCH', error: '...' };
  if (!p.askedAt) return { ok: false, code: 'NOT_ASKED', error: '...' };
  if (p.answer !== 'yes') return { ok: false, code: 'NOT_CONFIRMED', error: '...' };
  if (isProposalExpired(p)) return { ok: false, code: 'PROPOSAL_EXPIRED', error: '...' };
  return { ok: true };
}
```

**错误码**（便于调用方区分）：

| code | 含义 |
|---|---|
| `CONFIRMATION_REQUIRED` | user_directed 没有 proposal |
| `KIND_MISMATCH` | proposal 的 kind 和操作不一致 |
| `NOT_ASKED` | 有 proposal 但没问过 |
| `NOT_CONFIRMED` | 问了但答案不是 yes |
| `PROPOSAL_EXPIRED` | proposal 过期了 |
| `TERMINAL_STATE` | 已经是终态 |
| `INVALID_TRANSITION` | 状态转换不允许 |
| `NOT_FOUND` | 没有这条 Goal |
| `ALREADY_DONE` | 已经是目标状态（幂等） |

### 4.7 惰性过期

```js
export function expireProposals(now = Date.now())
// → { ok, expired: string[] }
```

**在 `readCompanion` 时顺便清理？** 还是**单独调用**？

**我建议**：
- **不在 `readCompanion` 里清**（读不应该写盘）
- 在 `proposeCompletion` / `markConfirmationAsked` / `answerConfirmation` / `endGoal` 的**写入时**顺手清理
- 另外导出 `expireProposals()` 供测试和将来手动调

**为什么**：机主要求"惰性过期检查，不增加定时任务" ✅
