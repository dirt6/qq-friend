## 二、真正的意外：不是聊天记录大，是 prompt 快照大

抽 40 个会话逐字段量了一下：

| 字段 | 占会话体积 | 说明 |
|---|---|---|
| `inputMessages` | **44.5%** | 送进模型的完整消息列表（每轮一份） |
| `systemPrompt` | **26.1%** | 人设 + 经验 + 表情包 + 工具（每轮一份，约 9000 字） |
| `userPrompt` | **17.0%** | 本轮拼的提示词（每轮一份） |
| `messages` | **8.5%** | **真正的聊天记录** |
| `excludedTools` / `promptAnchorState` / `trigger` 等 | 3.9% | 元数据 |

### 换算

```
1304 个会话 × 107 KB ≈ 135 MB
其中聊天记录只占 8.5%  ≈ 11 MB
剩下 87.6%（约 118 MB）是「每轮又存了一份人设和上下文」
```

**一句话**：**不是聊天记录占地方，是每一轮都把完整的人设和输入消息又存了一遍。**

## 三、几个和预期不一样的事实

### 1. 没有「717 turns 那种长会话」

| 指标 | 实际 |

| 会话数 | 1304 |
| 消息数 | 4390 |
| 平均每会话 | **3.4 条** |
| 最大会话 | 22 条消息 / 135 KB |
| 消息数 ≥100 的会话 | **0 个** |

**每来一批消息就新建一个会话**，不是"一个私聊一个长会话"。

所以「Session 轮换」这个需求 **在现在的实现里不存在** —— 它天然就是每轮一个。

### 2. 1304 个会话全是同一个 chatKey

```
private:1846383180  1304 个
```

没有群聊会话（或者群聊会话已被清理）。全部是跟你一个人的私聊。

### 3. 聊天存档和 Session **有重叠，但都不是大头**

| | 数量 | 消息数 | 大小 |
|---|---|---|---|
| `data/messages` | 1 个会话 | **5352 条** | 1.4 MB |
| `data/sessions` | 1304 个 | 4390 条 | 135 MB |

`messages` 是「全局流水」（每句话一条，1.4 MB），`sessions` 是「每轮快照」（同一句话跟着 prompt 又存了一遍）。

**重叠的部分只有 1.4 MB**，不是浪费的主因。真正浪费的是第二节那 118 MB prompt 快照。

### 4. DSH 还有 28.5 MB

`data/dsh-home` 105 个文件 = **DSH 那边的会话记录**（每轮 `dsh --session-id` 的存档）。

也就是说同一轮对话，现在存在**三个地方**：
1. `data/messages`（聊天流水，1.4 MB）
2. `data/sessions`（每轮快照，135 MB，其中 8.5% 是消息）
3. `data/dsh-home`（DSH 自己的会话，28.5 MB）

## 五、我建议的方案（等你确认再动手）

### 5.1 归档：剥离 prompt 快照，不动聊天记录

归档时**保留**：`id` / `chatKey` / `startedAt` / `endedAt` / `status` / `messages` / `usage` / `finishReason` / `trigger*` / `model`
归档时**剥离**：`systemPrompt` / `userPrompt` / `inputMessages` / `excludedTools`

**效果**：107 KB → 约 10~15 KB（保留 8.5% + 元数据），135 MB → 约 15 MB。

**风险**：归档后的会话不能再"从那一刻继续聊"（prompt 没了）。但：
- 这些会话都是 `done` 状态，本来就不会继续
- 聊天记录、时间、用量都还在，**记忆不丢**

**你要确认的**：这样算不算"改变 Session 格式"？我理解你的要求是"活跃会话格式不变"，归档文件可以换一种更省的结构。

### 5.2 清理：分四档，默认只清最老的一档

| 档 | 条件 | 动作 |
|---|---|---|
| 活跃 | 最近 7 天 | 原样 |
| 已归档 | 7~90 天 | 剥离快照，移到 `sessions/archive/` |
| 过期 | 90 天以上 | **默认不删**，只在超过容量阈值时提示 |
| 长期保留 | 机主手动标记 | 永不自动删 |

按当前数据（全部在 30 天内），**没有可清理的**。这套规则是为将来准备的。

### 5.3 不重复保存

短期的：归档时剥离 prompt 已经解决了 90% 的重复。

长期的（阶段 2）：`systemPrompt` 改成**存 hash + 引用**（人设变了才存新的），但那要改格式，**不在 1.5.7 做**。

### 5.4 面板 Session 管理页（你说的那个）

字段：当前活跃 / 已轮换 / 大小 / 最后活动 / 是否重要任务 / 归档状态 / 手动保留和删除。

**放在 1.5.8 之后或阶段 2**，这一轮先把归档和清理的后端能力做出来。

这样以后能回答"那一轮她看到的上下文有多长、是不是同一版人设"，但不用留全文。
