### 2.3 这意味着什么

**她聊完天不会更新 `currentGoal`**。刚才 13:59 那轮她决定「把视频花费的事说开」，这个目标写进了 `autonomous.json`，但：

- 你在 QQ 里跟她说话时，**她不知道自己在等什么**
- 下一轮聊天用的是 `sessions.js` 的会话记录，**没有 `pendingNextStep`**
- 只有下次自主活动醒来，才会读回这个目标

**所以「跨模式连续」现在是断的。**

## 三、阶段 2 要做什么

### 3.1 建 `src/companion/state.js`

```js
// 单一真源：data/companion-state.json
{
  "version": 1,
  "goal": { "text": "…", "source": "autonomous" | "chat", "since": ts },
  "topic": { "text": "…", "since": ts },
  "pending": [
    { "id": "p-xxx", "text": "等老大回应", "status": "pending" | "done" | "dropped",
      "source": "chat", "at": ts, "settledAt": null }
  ],
  "mood": { "label": "…", "since": ts } | null,
  "updatedAt": "…"
}
```

**写入口**（全部走 1.5.3 的 `state-store`）：

```js
readCompanion()                       // 只读
updateCompanion(fn)                   // 锁内读-改-写
setGoal(text, source)                 // 设目标
clearGoal(reason)                     // 清目标
addPending({ text, source })          // 加待办
settlePending(id, outcome)            // 结算（done / dropped）
setTopic(text)                        // 设当前话题
```

### 3.2 迁移（一次性，不留双写期）

**D2 明确不允许两个地方分别修改同一字段**，所以不做双写：

```
① 写迁移脚本：把 autonomous.json 的 currentGoal/pendingNextStep 搬进 companion-state.json
② 改 autonomous 的 5 个读写点 → 指向 companion
③ autonomous.json 的旧字段**保留但不再写**（只读兼容），标 deprecated
④ 面板如果读了旧字段，改成读新字段
```

**回滚点**：迁移脚本先 `--dry`，把要搬的数据打出来。

### 3.3 聊天侧接入

这是阶段 2 的核心价值——**聊天也要读写 Companion State**：

| 时机 | 动作 |
|---|---|
| 聊天开始（`wake`） | 读 `goal` / `pending` / `topic`，注入 prompt |
| 她说了"等你回话"这类 | 写 `pending` |
| 老大回话（settle） | 把对应 `pending` 标 done |
| 她明确说"这事说开了" | `clearGoal` |

**注意**：**不改变她的行动逻辑**。只是把"她本来就在想的事"变成显式的、两个模式都能看到的状态。

### 3.4 注入 prompt

在 `personaPatchFile` 或 `prompt.js` 里加一段（很短）：

```
【你现在】目标：把视频花费的事说开｜在等：老大回应
```

**不塞长内容**（她本来就有记忆库和日记）。

## 四、和 Memory Hub 的边界（机主要求在阶段 2 就定）

| | Companion State | Memory Hub |
|---|---|---|
| **是什么** | **当前状态**：正在做什么、在等什么、聊到哪 | **长期记忆**：经验、日记、群友印象 |
| **生命周期** | 短（天级），会过期、会被结算 | 长（月级），累积 |
| **谁写** | 聊天 + 自主活动 | Memory Hub 统一入口（阶段 4） |
| **存哪** | `companion-state.json` | `learned.json` / 日记 / `data/memory/` |
| **典型问题** | "她现在在等什么？" | "她记得老大喜欢什么？" |

**关键边界**：

- Companion State **引用**记忆（比如 `topic` 可以指向某条经验），但**不复制**记忆内容
- Memory Hub 不存"当前在做什么"——那是 Companion State 的事
- **两者都用 `state-store` 的单写者**，但**不同的文件**

**这条定下来，阶段 4 就不会出现字段重复。**

## 六、要你确认的三件事

1. **`mood` 要不要放进 Companion State？**
   她在日记里写心情（`- 心情：开心｜…`），但那是**记录**不是**当前状态**。
   我倾向**先不放**——情绪状态很难准确定义，容易变成假数据。
2. **`pending` 允许多条吗？**
   现在 `pendingNextStep` 只有一条。我建议允许多条（带 id），否则"等她回话"和"明天提醒他"会互相覆盖。
3. **聊天侧写 `pending` 的触发条件？**
   最保守：只在**她明确说了"等你回话/回头再说"**这类话时写。
   激进：每轮都更新"当前话题"。
   我建议**先只做保守那半**，观察一段时间再加。

确认后我写 2.2 的模块。
