## 三、发现的问题

### 问题 1（中）：`clearGoal` 的名字与语义不匹配

**代码**：

```js
export function clearGoal({ source = 'unknown' } = {}) {
  // 2.6.1：clearGoal 的语义变成「当前方向不再作为 active」→ 转 completed
  ...
  cur.status = 'completed';
  cur.reason = cur.reason || '方向变成完成状态（2.6.1 兼容行为）';
}
```

**唯一调用点**（`plugins/autonomous/index.js:245`）：

```js
// settleChatPending 里
if (cg && settledTexts.includes(cg.text)) clearGoal({ source: 'autonomous' });
```

**上下文**：老大回话 → 结算了 pending → 如果 goal 文本和那条 pending 相同 → 清 goal。

**语义分析**：

| 场景 | `completed` 对不对 |
|---|---|
| goal = "等老大回话"，pending = "等老大回话"，老大回了 | ✅ 对（这件事完成了） |
| 未来的调用点想"清空当前方向" | ❌ 会被标成"完成了"，但实际可能是"不做了" |

**结论**：**当前唯一调用点语义恰好匹配**，但函数名 `clearGoal`（清除）隐含"清空"而不是"完成"。

**风险**：2.6.3 引入 `completeGoal` / `cancelGoal` 后，如果还有人调 `clearGoal` 想清空，就会污染历史（把取消记成完成）。

**最小修复建议**（不实施）：

- 给 `clearGoal` 加 `@deprecated` 注释，明确"过渡接口，2.6.3 后移除"
- 或在函数名上留注释：**它现在的语义是 `completeGoal`**

### 问题 2（中）：`MAX_PAUSED_GOALS` 完全没被检查

**实测**：

**按设计第十五节 2.6.4 才做容量管理**，所以 2.6.1 不实现是**符合阶段划分**的。

**但**：现在这个常量是"死代码"，容易让人误以为已经生效。

**最小修复建议**（不实施）：

- 或者在 `setGoal` 里加一行 TODO

### 问题 3（低）：权限表无法区分三种确认方式

**实测**：

```js
canOperate('user_directed', 'complete')   // false
canOperate('user_directed', 'cancel')     // false
canOperate('user_directed', 'supersede')  // false
```

**三者都是 `false`，同一个布尔值。**

**设计文档**说："完成需要确认已实现，取消需要明确放弃，取代需要确认原目标已失去意义"——**三种不同的确认语义**。

**判断**：**属于 2.6.3 的范围**（2.6.1 只做模型），但需要明确记录：**现在这个表只表达"能不能做"，不表达"怎么确认"**。

**最小修复建议**（不实施）：

- 在 `GOAL_PERMISSION` 的注释里写明："这里只表达能不能做；怎么确认由 2.6.3 的接口各自实现"

---

### 问题 4（低）：`setGoal` 的 `reason` 是固定文案

**代码**：

```js
cur.reason = cur.reason || '被新方向取代，暂时搁置';
```

**问题**：这个文案暗示"被取代"，但实际状态是 `paused`（暂停）。

**设计文档**：`superseded` 才是"被取代"，`paused` 是"暂时搁置"。

**影响**：历史记录里看到"被新方向取代"，但状态是 `paused`，**语义不一致**。

**最小修复建议**（不实施）：改成 `'出现新的方向，暂时搁置'`。
