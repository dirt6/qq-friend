## 二、`createAutonomousGoal` 的复用情况

```js
export function createAutonomousGoal({ text, evidence, knownRounds = null } = {}) {
  const v = validateGoalEvidence(evidence, { knownRounds });   // ① 校验证据
  if (!v.ok) return { ok: false, error: v.error, code: v.code };

  const r = createGoal({ text, source: 'autonomous' });        // ② 复用 createGoal
  if (!r.ok) return { ok: false, error: r.error, code: r.code, capacity: r.capacity };
  return { ok: true, goal: r.goal, created: r.created, evidence: {...} };
}
```

**复用情况**：✅ **完整复用**

- 同文本去重：`createGoal` 的 `sameActive` / `samePaused` 分支
- 来源升级：`createGoal` 的 `sourceHistory` 逻辑
- 容量限制：`createGoal` 的 `computeCapacity`
- 并发：`createGoal` 的 `updateCompanion` 锁

**它只多了一层证据校验，其余全部透传。**

## 三、问题：三种收口方案的兼容成本

### 方案 A：`createGoal` 加 `allowAutonomous` 开关

```js
export function createGoal({ text, source = 'autonomous', allowAutonomous = false } = {}) {
  if (source === 'autonomous' && !allowAutonomous) {
    return { ok: false, code: 'EVIDENCE_REQUIRED', error: '自主 Goal 必须走 createAutonomousGoal' };
  }
  ...
}
```

**`createAutonomousGoal` 内部传 `allowAutonomous: true`。**

| 项 | 影响 |
|---|---|
| 生产代码 | ✅ 零改动 |
| `createAutonomousGoal` | ✅ 一行改动 |
| **测试** | ❌ **~60 处要加 `{ allowAutonomous: true }`** |

**兼容风险**：**高**（大量测试改动，容易引入新 bug）。

### 方案 B：`createGoal` 改名成内部函数

```js
function createGoalInternal({...}) { ... }           // 不导出
export function createGoal({ text, source }) {       // 公开的，但有校验
  ...
}
export function createAutonomousGoal({...}) { ... }
```

**问题**：`createGoal` 的公开签名变了（要 evidence），**测试全废**。

**兼容风险**：**极高**。

### 方案 C：不改 `createGoal`，只在调用点加约束

- 保持 `createGoal` 不变
- **加 JSDoc `@internal`**，说明它会绕过证据校验
- **B5 只用 `createAutonomousGoal`**
- **靠代码审查保证**

**兼容风险**：**零**（不改任何代码）。

**但**：**没有强制**——架构上还是能绕过。

### 方案 D：`createGoal` 保留，新增 `createUserGoal`

```js
export function createGoal({...}) { ... }            // 保持原样（内部用）
export function createUserGoal({ text, reason }) {   // 新增：只建 user_directed
  return createGoal({ text, source: 'user_directed' });
}
export function createAutonomousGoal({...}) { ... }  // 已有
```

**B5 用 `createAutonomousGoal`，聊天侧用 `createUserGoal`。**

**兼容风险**：**零**（`createGoal` 不变）。

**但**：`createGoal` 还是能绕过。

## 四、我的建议

### 关键判断：**收口的目标是什么？**

如果目标是"**B5 不会调错**"：

- **方案 C 就够**——加 `@internal` 注释 + B5 代码审查

如果目标是"**架构上不可能绕过**"：

- **只有方案 A 能真正做到**
- **代价是 ~60 处测试改动**

### 我倾向：**方案 A 的变体（默认参数 + 只改必要测试）**

**但有一个更轻的办法**：

```js
export function createGoal({ text, source = 'autonomous', _from } = {}) {
  // _from 是内部调用标记：只有 createAutonomousGoal / createUserGoal 会传
  if (source === 'autonomous' && _from !== 'autonomous-verified') {
    return { ok: false, code: 'EVIDENCE_REQUIRED', error: '...' };
  }
  ...
}
```

**测试改成**：用 `createAutonomousGoal` 或 `createUserGoal` 建数据，**不再直接调 `createGoal`**。

**这样测试也"正确"了**——它们本来就不该直接建 autonomous Goal。

**代价**：测试要改 ~60 处。

**但**：**这是"让测试用正确的方式建数据"**，不是"为了过测试而加参数"。
