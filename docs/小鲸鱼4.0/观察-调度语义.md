### 现象 1：`nextWakeAt` 被我的手动操作推后了


**算法**（`plugins/autonomous/index.js:982`）：

```js
function nextWakeAt(nowTs, intervalHours) {

}
```

**配置**：`intervalHours: 3`

**结论**：这是我的操作副作用，**不是 bug**。

**处理**：不改 `nextWakeAt`，让生产自然跑到 18:29。

## 三、机主的判断：两种调度语义要分开

> 两种调度明确区分：
> - **固定周期**：例如每 3 小时自主活动一次
> - **单次唤醒**：例如 90 分钟后回来检查某件事
>
> 两者是不同的调度语义，**不应仅凭 `wakeAfterMinutes` 就认为已经建立了单次预约**。

**这个区分很重要**：

| | 固定周期 | 单次唤醒 |
|---|---|---|
| 语义 | 「每 N 小时该看一次世界」 | 「N 分钟后回来确认这件事」 |
| 来源 | 配置 `intervalHours` | 她自己的 `wakeAfterMinutes` |
| 生命周期 | 循环，每轮重置 | 一次性，用过就清 |
| 现在状态 | 正常工作（3 小时） | **`enabled: false`，完全没生效** |

**现在的实际效果**：她说「等老大回话，90 分钟后看看」，但**系统听不见**，要等 3 小时固定周期。

**这不是紧急 bug**（她只是不够及时），但**是真实的功能缺口**。
